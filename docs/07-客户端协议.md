# 07 · 客户端 API 与事件协议

> 状态：设计草案。路径与数据结构为提议，尚未提供可调用服务。

## 一、协议目标

Web、CLI、Desktop 和服务集成都通过稳定 API 操作 Session/Turn，不直接调用内部 Agent Loop。第一版优先采用 HTTP 命令接口 + SSE 事件订阅；WebSocket 可在确有双向实时需求时补充，不应让业务语义绑定某种传输。

基础约定：

- API 版本前缀为 /v1；协议变更必须维护兼容性和升级说明。
- 所有写请求带请求幂等键（Idempotency-Key）。
- 所有关键响应带 requestId 和服务器端真实 ID。
- Event Stream 按 Session 内 sequence 单调有序；客户端按 sequence 去重。
- 身份验证、租户/工作区权限不由请求体中的 ownerId 决定。

## 二、候选命令接口

| 方法与路径 | 用途 | 重要约束 |
| --- | --- | --- |
| POST /v1/sessions | 创建会话 | 创建者身份来自服务端身份上下文 |
| GET /v1/sessions/{sessionId} | 查询会话快照 | 返回状态与最新 sequence |
| POST /v1/sessions/{sessionId}/turns | 提交用户输入 | 需幂等键；相同会话活跃 Turn 策略明确 |
| GET /v1/sessions/{sessionId}/events?after=N | SSE 订阅/重放 | 从 N 之后回放，游标过期明确报错 |
| POST /v1/turns/{turnId}/cancel | 请求取消 | 幂等；不保证可撤销已执行副作用 |
| POST /v1/turns/{turnId}/steer | 运行中追加指令（实验） | 带 expectedTurnId，避免误投 |
| POST /v1/approvals/{approvalId}/decision | 审批工具 | 身份、过期、ToolCall ID、参数指纹全校验 |
| GET /v1/sessions/{sessionId}/artifacts | 查询产物 | 不暴露任意宿主文件路径 |

接口名与字段在实现前由类型定义和 OpenAPI/JSON Schema 冻结；此表仅为建议合同。

## 三、请求与事件示例

提交 Turn：

```json
{
  "message": { "role": "user", "content": "读取项目 README 并总结" },
  "mode": "agent",
  "expectedSessionVersion": 3
}
```

服务端接受后返回：

```json
{
  "requestId": "req_...",
  "turnId": "turn_...",
  "state": "queued",
  "sessionId": "session_..."
}
```

SSE 事件示例（示意结构）：

```json
{
  "schemaVersion": 1,
  "eventId": "evt_...",
  "sessionId": "session_...",
  "sequence": 42,
  "turnId": "turn_...",
  "type": "ToolCallPrepared",
  "occurredAt": "2026-10-24T00:00:00Z",
  "payload": { "toolCallId": "call_...", "toolName": "Read" }
}
```

所有示例 ID 都是占位值，不代表既有实现。

## 四、命令幂等和并发

- 同一身份、作用域与幂等键的重试应返回同一操作结果或明确的处理中状态。
- 同一幂等键但请求体不同必须返回冲突，禁止悄悄执行第二次。
- 提交与取消发生竞态时，以服务端已持久化的状态转换为准。
- 对活跃 Turn 的新指令必须区分队列、拒绝和 Steering 三种意图。
- 内部工具调用不得由客户端直接构造并发往 Host。

## 五、错误模型

推荐统一格式：

```json
{
  "error": {
    "code": "TURN_CONFLICT",
    "message": "会话中存在正在执行的任务",
    "retryable": false,
    "requestId": "req_..."
  }
}
```

建议错误集合：

- INVALID_ARGUMENT / UNAUTHORIZED / FORBIDDEN / NOT_FOUND
- SESSION_NOT_READY / TURN_CONFLICT / INVALID_STATE
- APPROVAL_EXPIRED / APPROVAL_MISMATCH / PERMISSION_DENIED
- PROVIDER_UNAVAILABLE / MODEL_CAPABILITY_UNSUPPORTED
- TOOL_EXECUTION_FAILED / TOOL_OUTCOME_UNKNOWN
- CONTEXT_BUDGET_EXCEEDED / EVENT_CURSOR_EXPIRED

错误码机器可读且稳定；对外 message 本地化，不能泄露访问令牌、模型密钥、宿主真实私有路径。

## 六、断线恢复

1. 客户端保存最后成功消费的 sequence。
2. 重连发送 after=sequence，服务端从事件日志重放。
3. 服务端如果已清理旧事件，则明确返回 EVENT_CURSOR_EXPIRED 或 SnapshotRequired；客户端重新取快照。
4. 客户端重连不能自动提交原消息产生第二次 Turn；写请求通过幂等键解决。
5. 事件展示与服务端执行分离，关闭浏览器不代表取消正在运行的 Turn。

## 七、协议安全验证

- Cookie/token 鉴权、跨来源限制、速率限制、请求大小上限。
- 仅返回当前身份可访问的 Session 与产物。
- 审批决定验证审批所属 Turn、工具和参数指纹。
- 事件回放经过用户权限过滤，不能跨 Session 串流。
- 请求 ID、日志关联 ID、事件 ID 分离，防止将幂等键作为授权凭证。
