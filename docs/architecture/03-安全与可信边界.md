# 安全与可信边界

> **状态：安全设计基线草案**。涉及 Linux 内核的历史测试仅针对指定环境与提交，不构成当前仓库的安全证明。

## 一、威胁模型

模型输出、用户提供的文件、网页内容、第三方工具响应、项目说明文字，以及客户端提供的元数据，都不具备自动授权能力。攻击者可能伪造工具名称、参数、调用 ID、路径、身份、收据，或利用取消/超时竞态绕过检查。

必须区分以下主体：用户与凭据、客户端、模型适配器、Kernel、Scheduler、Tool Host、隔离 Worker 和审计存储。**只有可信授权组件和宿主边界可以放行真实副作用。**

## 二、执行入场检查

工具开始前，应由可信侧核验：

1. Session/Turn/ToolCall 归属关系与唯一标识；
2. 完整参数及 Schema、工具版本、冻结的工具目录；
3. 操作者身份、会话授权、审批是否绑定精确参数和有效版本；
4. Writer Lease/Fencing Token 是否仍有权执行；
5. 工具风险等级和隔离要求能否被当前宿主满足；
6. 审计 Intent 是否已持久化；失败则拒绝执行。

模型声明“已经获得权限”不能替代这些检查。

## 三、进程与操作系统隔离

- **namespace/Bubblewrap**：限制文件视图、进程/网络隔离等；必须验证实际命名空间和挂载结果。
- **cgroup v2**：约束 CPU、内存和进程数，关注专属进程组及整组清理。
- **seccomp**：限制系统调用，需验证 BPF 策略真正安装；并非文件系统权限的替代物。
- **文件系统工作区**：明确可读、可写、数据库和凭据目录；拒绝符号链接、路径穿越和混杂挂载造成的越界。
- **Host 身份**：Worker 自报 PID/命名空间不足以证明可信；可信方需核对 OS 实际信息。

缺少任一部署必需条件时，**拒绝启动**，而不是退化为无遮蔽的高权限模式。

## 四、结果与恢复

执行宿主必须产生可核对的证据；Kernel 事件与 Host 账本可以相互核查，但**不能因此声称数据库事务与外部文件/网络副作用具有原子性**。记录不完整时标记 UNKNOWN，通过对账、人工审核或目标系统自身的幂等协议处置。

## 五、生产级缺口

历史文档曾记录 Bubblewrap、seccomp、cgroup 等增量验证，但完整专属 cgroup 正向验收、数据库权限隔离、真实生产鉴权、审核人身份绑定以及跨宿主恢复仍需要独立证明。因此本文不标记“生产就绪”。

## 六、验收边界

- 模型注入/伪造批准不可提升权限。
- 租约被撤销后不再启动新副作用。
- 超时中断不把 UNKNOWN 当失败。
- 不支持的 Linux/宿主环境必须 fail closed。
- OS 资源和网络/文件访问边界有真实探针及失败案例。
- 审计日志失效不能继续放行高风险操作。
