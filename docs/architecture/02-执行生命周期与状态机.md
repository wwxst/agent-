# 执行生命周期与状态机

> **状态：规范候选；不表示当前已有对应实现。**

## 一、对象与标识

- **Session（会话）**：持久事件序列的归属边界；同一可变 Session 不能出现两个未经协调的写入者。
- **Turn（轮次）**：一次用户请求引起的模型/工具生命周期；具有不可重复写入的终态。
- **Step（步骤）**：一次模型请求、工具批次或上下文整理阶段。
- **ToolCall（工具调用）**：带唯一 ID、版本、参数与对应意图/收据的单次请求。
- **Command（命令）**：被持久接受的用户操作，不等于已经成功执行的 Turn。

## 二、主路径

```text
Command accepted
    -> Turn admitted
    -> Context projection & budget check
    -> Provider request & complete message
    -> ToolCall validation / immutable tool snapshot
        -> no tool calls: completed
        -> tool calls: Intent persisted
             -> Host authorization / execution
             -> Receipt or Outcome Unknown
             -> ToolResult projection
             -> next model Step
```

**关键屏障：** 不得执行尚未获得完整、可验证参数的 ToolCall；高风险调用执行前必须已有可信 Intent 和对应授权；不得把文本增量视为模型的最终完成事件。

## 三、状态模型

建议区分：

- `queued`：已接收但尚未入场；
- `running_model`：模型步骤进行中；
- `running_tools`：存在已准入工具；
- `cancelling`：已经请求停止，但执行结果不一定已知；
- `completed`、`failed`、`cancelled`：明确终态；
- `recovery_required`：恢复侧观察到未决事件或不可信状态，需先对账或人工处置。

`recovery_required` 在这里是**恢复判定**，不强制要求它成为数据库里与 TurnState 等价的枚举值。旧设计文档中的 `interrupted` 也可作为外部表示；最终事件 Schema 必须统一并版本化。

## 四、取消、租约丢失和 UNKNOWN

| 场景 | 应做的事 | 不得做的事 |
| --- | --- | --- |
| 用户取消但工具未开始 | 不启动新调用，记录取消事实 | 伪造工具已执行 |
| 已开始的工具收到取消 | 通知 Host 中止并等待可信结果 | 假定 AbortSignal 一定撤销副作用 |
| 租约丢失 | 隔离旧执行者，拒绝新动作 | 写虚假的普通 `cancelled` |
| Host 消失或收据不完整 | 记录结果未知，进入对账 | 自动重做非幂等操作 |
| 模型响应截断 | 根据明确规则拒绝或标记异常 | 执行未完整确认的 ToolCall |

## 五、持久接受与幂等

Command Inbox 应以持久化身份和请求指纹去重：**同一个幂等键 + 同一内容**返回同一个 ACK；**同键不同内容**必须冲突。Command→Turn 绑定必须持久化，重发 ACK 不能重复产生轮次或工具副作用。

## 六、工具并发规则

默认从保守并发开始：只读且互不影响的任务可以并行；独占工具构成屏障。调用完成的收据按真实时序持久记录，而模型上下文按稳定关联关系输出结果。任何租约或收据提交失败，都需要先等待已启动任务收敛或标记 UNKNOWN，不能提前释放执行所有权。

## 七、最低验收

1. 文本完成、截断、非法工具参数、重复 ToolCall ID。
2. 双写者竞争、租约过期、事件序号冲突、未决 Turn 重开。
3. 多工具反序完成后模型上下文顺序确定。
4. 工具已启动而 Host 崩溃：禁止无证据自动重试。
5. 用户取消、租约失权、授权撤销有不同的可追踪结果。
6. 上下文压缩与 Checkpoint 不删除原始审计证据。
