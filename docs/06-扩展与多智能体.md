# 06 · Hooks、Skills、MCP 与 Subagents

> 状态：设计草案。除最基础 Hook 接口外，该文档主要定义 v0.2+ 的演进方向。

## 一、为什么扩展不应侵入 Agent Loop

内核负责少量稳定行为：状态转换、预算、调度、权限、事件、恢复。每增加领域功能就修改 Agent Loop 会造成难以测试的分支和多处状态来源。

扩展机制应提供受控、可观察的能力，不能跳过内核不变量。

## 二、Hooks

推荐的 Hook 阶段：

| 阶段 | 用途 | 是否允许阻止 |
| --- | --- | --- |
| beforeTurn | 补充已授权上下文、预检 | 允许 |
| beforeModelRequest | 观察/调整受控元数据 | 可拒绝，不可绕过安全预算 |
| afterModelResponse | 记录指标、结构化分析 | 不修改已持久化历史 |
| beforeToolCall | 风险提示、上下文检查 | 允许拒绝，不能提升权限 |
| afterToolCall | 收集结果摘要、审计 | 不改变执行事实 |
| onTurnFinished | 清理、统计、通知 | 不得阻止终态写入 |

Hook 要有运行时限、确定性调用顺序和失败策略。阻断型 Hook 出错默认拒绝动作；只读观测 Hook 失败应记录告警且不能破坏持久化提交。

## 三、Skills

Skill 由元信息、使用条件、说明文本及可选资源组成。

- Skill 为 Agent 提供操作知识，不天然成为受信任系统指令。
- 来源可为内建、用户安装、项目级、远程；必须保留来源与完整性信息。
- 启用 Skill 不意味着自动授予 Shell、网络、文件系统权限。
- 版本变化必须具备审计与回滚路径。
- 超大 Skill 文档应采用按需载入，不强行塞满上下文。

## 四、MCP 与第三方插件

- Tool Registry 允许来自 MCP 的动态工具，但使用命名空间避免与内建工具重名。
- 工具声明、权限、参数 Schema、超时和输出限制统一由本项目执行。
- 第三方工具可能返回包含提示注入的内容，应作为不可信数据提供给模型。
- 不运行任何未经明确授权的插件原生代码；插件沙箱与 Host 能力隔离单独设计。
- 外部插件升级后不静默扩大原有权限。

## 五、Subagent 模型

Subagent 是具有独立 Context、Turn 生命周期与工具权限的子任务执行单元，不是单纯把主 Agent 的系统提示词换成“你是子智能体”。

推荐任务结构：

```text
Parent Turn
    └─ Task(id, budget, capabilities)
         ├─ Child Session / Isolated Context
         ├─ Provider / Tool Policy
         ├─ Task Events
         └─ Result / Artifacts / Error
```

约束：

1. Child 继承父任务授权的子集，不得自动扩大权限。
2. 必须设置并发上限、调用预算、深度限制和超时。
3. Child 与 Parent 的消息历史默认隔离；结果以结构化摘要/产物引用传递。
4. Parent 取消后的 Child 行为需要明确，默认终止可取消子任务并标记不可确认副作用。
5. 所有子任务要能追溯 parentTaskId 与创建来源。
6. 子 Agent 向父 Agent 汇报“不知道/未完成/失败”的状态不能被美化成成功。

## 六、工作流不是 Agent Loop

可选的 Workflow Engine 管理 DAG、重试策略、任务依赖与定时。它使用 Kernel 提供的 Session/Turn API，不应绕过 Tool Host 或自行写消息记录。

视频剪辑等领域能力建议采用：“高层任务规划 + 受限媒体工具 + 可追踪工件 + 人工预览与确认”，而不是让模型在 Shell 中无限自由执行 FFmpeg。

## 七、DeepSeek Harness 带来的生命周期设计补充（提议）

DeepSeek Harness / Cordis 的参考价值不只是“可以装插件”，而是组件的**作用域、依赖、注册所有权及可逆卸载**。参见 [专项研究](09-DeepSeek-Harness-借鉴评估.md) 与 [ADR 0002](adr/0002-能力组合与可信内核边界.md)。

- Provider、Tool Adapter、Context Contributor、Skill、Transport 等能力通过接口装配，但不允许普通插件替换 Turn 状态机、权限根和事件提交语义。
- 每个 Agent/Task 有独立 ResourceScope。Scope 拥有它注册的监听器、工具、Hook、连接及子任务；结束后必须幂等清理。
- 初始化失败先回滚已注册的资源；卸载插件之前必须停止接收新调用并 drain 正在执行的任务，避免审批后在另一个插件实现中执行。
- 运行中 Turn 绑定插件及工具 Schema 版本；配置变更默认仅影响后续 Turn。热重载属于后续明确的安全与兼容性任务。
- Profile 可以定义 Coding、Browser、Media 等能力集合，但 Profile 不能直接签发超过用户/宿主许可的权限。
- 插件事件分两种：已持久化的事实（受 Kernel 约束）与进度/模型流片段（瞬态）；监听回调不能伪造提交成功。
- 默认 Turn 预算不可通过安装插件关闭，沙箱隔离能力必须由 Tool Host 实施并校验。

### 扩展层的最小测试

必须测试：插件初始化回滚、重复 dispose、执行中卸载、Agent 间作用域泄漏、工具合同版本冲突、运行中 Profile 切换和事件持久化先后顺序。当前只有设计草案，测试尚未实现。

## 八、演进次序

- v0.1：固定工具注册表、基础 Hook、独立模型/宿主边界。
- v0.2：Skills 和 MCP 适配器、稳定的插件生命周期。
- v0.3：Subagent、子任务预算与可恢复任务调度。
- v0.4+：远程 Worker、工作流与媒体领域扩展。
