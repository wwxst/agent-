# 28 · M3 Linux Sandbox 启动可信根、临时空间预算与就绪超时

> 这是对 [27 Bubblewrap Tool Host](27-M3-Linux-ToolHost-Bubblewrap-强制隔离.md) 的后续安全加固，**不开放新的工具权限**。旧的非沙箱 Host API 继续用于兼容，不代表所有 Host 自动获得 OS 保护。

## 安全修复

1. **阻止不受信任的 launcher 替换**：`buildBubblewrapLaunch` 除校验 `binaryPath` 为真实可执行文件外，还要求其 `realpath` 位于显式配置的 `runtimeReadOnlyDirectories` 之一。曾经 `binaryPath` 可以指向 SQLite RW 目录下的可执行脚本；该位置可以被 Worker 修改，不能充当隔离启动器的信任根。现在在**启动之前**拒绝。部署方应把 Bubblewrap 的二进制放在受信系统只读运行时目录，确保持久 DB 目录不可影响可执行文件；这不是二进制代码签名或 TOCTOU 的完整解决方案。
2. **私有 `/tmp` 硬容量**：在 `--tmpfs /tmp` 前加入 Bubblewrap 的 `--size BYTES --perms 0700`。默认分配 16 MiB 的私有临时目录；可信宿主可显式设置 `privateTmpBytes`，受限范围 1–128 MiB。此限制只控制该 tmpfs 的最大文件空间，不是整个 Worker 的内存或 CPU 限额，也不能限制数据库目录的 RW 空间。
3. **Worker 就绪超时**：`ProcessToolHost` 在等待 Bubblewrap 启动及 namespace attestation 的 `ready` 握手期间启动定时器。超时直接终止沙箱并返回 `HOST_SANDBOX_UNAVAILABLE`；不会让首个工具调用一直悬挂、不会降级回未隔离进程。可信配置支持 `startupTimeoutMs`（1–60,000 ms），不设置时有与 Host 超时关联的安全默认值。
4. 保留 Linux user/mount/network/PID namespace 身份验证、只读代码、专用 SQLite RW 台账目录、Host Fencing/Intent/Receipt、未知结果禁止自动重试等所有已有边界。

## 使用示例

```ts
const sandbox = {
  binaryPath: '/usr/bin/bwrap',
  runtimeReadOnlyDirectories: ['/usr'],
  privateTmpBytes: 16 * 1024 * 1024,
  startupTimeoutMs: 5_000,
};

const host = new ProcessToolHost('/dedicated-state/agent.sqlite', 4_000, sandbox);
```

请按 Linux 发行版、Node 真实路径和 Loader 实际情况调整 runtime。Bubblewrap 必须安装在允许的目录中。目录布局不符时**拒绝启动**，不是在目录外放宽 launcher 路径。

## 故障测试

新增 `tests/linux-sandbox-tool-host.test.ts` 中的 **4 项**：

- 可执行脚本伪装成 bwrap 且位于 Writable SQLite 目录时必须拒绝；
- TMPFS 的实际 argv 含 `--size`/`--perms`，超界容量与非法超时配置拒绝；
- **真实 Bubblewrap namespace** 中写入超过私有 `/tmp` 容量的文件会遇到 `ENOSPC`；
- 启动 `ready` 超时时，在有真实 Bubblewrap 的环境中必须拒绝执行，不产生任何 Host STARTED 行。

前期累计 212 项，本轮新增 4 项，目标累计 **216 项**；其中真实 Linux 测试的执行与跳过情况需要以 PR 的 GitHub Actions 为准。

## 尚未完成

- 没有 cgroups v2 的整进程树 CPU/内存/PID 配额、seccomp BPF 系统调用策略、可信二进制签名或管理员授权部署策略。
- 不具备可任意执行未经审核代码的生产沙箱；数据库所在目录仍向 Worker RW 挂载，所有原有外部副作用/高风险工具仍禁用。
- OS 级沙箱**仍需显式启用**，旧非沙箱 Host 未被自动升级；今后应提供默认强制的生产启动入口，避免配置遗漏。
