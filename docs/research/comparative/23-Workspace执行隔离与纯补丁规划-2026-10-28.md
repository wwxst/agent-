## 2. 两项实际反例

**OBS-03：可写子树不保证其它路径对应的 inode 不变。** 研究测试在可写 `src` 中预先放置一个指向受保护 `spec/protected.txt` 的硬链接。虽然 `spec` 的路径是只读挂载，写入 `src` 中的硬链接仍然改变了该 inode 的内容。因此将用户已有仓库局部 `--bind` 为可写，不等价于保护仓库中其他文件的**内容**。第 22 号报告的路径/symlink 测试仍成立，但适用范围必须收窄。

**OBS-04：复用只读 Host 的可写数据库目录可能让项目测试代码修改账本。** 原有 `buildBubblewrapLaunch()` 为受信任的 `read.echo/read.sleep` Worker 挂载专用 SQLite 目录是必要设计；但研究中若直接复用该 argv 来运行项目测试脚本，测试进程可对可写 DB 路径写入字节。这不是生产白名单 Worker 被突破，而是候选 Workspace 设计的**权限混用风险**。

Issue 跟踪：[Workspace mount / hardlink / ledger 设计阻塞 #37](https://github.com/wwxst/agent-/issues/37)。

## 3. 隔离修正：运行副本而非直接修改原仓库

研究用 `WORKSPACE-STAGE-01/02` 采用：

1. 可信准备步骤把要操作的代码与只读测试文件**逐个复制成新文件**，不保留原仓库硬链接的 inode 关系。
2. Bubblewrap 执行侧只能看到 Stage；Stage 整体只读，只有 Stage 的 `src` 可写；**原仓库与 Host SQLite 目录完全不挂载**。
3. 执行进程无法读写 SQLite、无法修改真实原仓库或 Stage 受保护测试目录，且无法从只读 Stage `spec` 建立新硬链接到可写 `src`。
4. 执行进程能修改 Stage `src`，并按固定命令运行实际 `node --test`：测试先失败，修复后通过；真实原仓库无修改。

**限制**：此测试用启动器通过从旧 Host argv 中删除 SQLite 挂载构造 Stage 的命名空间，仅用于实证。正式实现**必须有独立的 Workspace sandbox builder**，不能依赖易碎的 argv 改写，也不能允许模型操纵挂载表。Stage 进程目前没有生产 Lease、审批、Host Ledger、Seccomp+cgroup 组合或进程树取消保证。

## 4. 合并候选：纯补丁规划而不是写文件

新增 [`packages/tool-host/src/workspace-patch.ts`](../../../packages/tool-host/src/workspace-patch.ts)：

- `validateWorkspacePatch(input)`：解析严格字段、规范化的相对路径、旧内容和新内容的字节界限、所期望的 SHA-256。
- `previewWorkspacePatch(content,input)`：对当前**提供的文本内容**做 SHA-256 版本校验，要求旧片段唯一，返回候选文本和其 SHA-256；过期版本、无匹配、重复匹配、超限均拒绝。
- 这是**纯函数模块**：不读取磁盘、不修改任何文件、不批准写入，也不提供任意模型执行入口。外部可信控制层仍必须处理文件身份、符号链接、原子写入及回滚/Unknown。

单元测试 `tests/workspace-patch.test.ts`：4 项规范性断言；`tests/workspace-staging-candidate.test.ts`：2 项真实 OS Stage 执行验证。

## 5. 下一步必须解决的协议与验收

| 边界 | 要求 | 本轮状态 |
| --- | --- | --- |
| 模型提案 | Patch + 基线 SHA-256，不能自行声明执行权限 | 纯预览器通过 |
| Control Host | 校验 Caller、Workspace、批准版本、Lease、持久 Intent/STARTED/Receipt | **未接入** |
| Stage / Test Host | 无数据库挂载、真实仓库不可见、资源与网络受限 | 特定 Linux CI 的 Stage 实验通过 |
| Apply / Commit | 可信进程复验原仓库文件版本，验证候选差异，采用安全原子提交 | **未实现** |
| 崩溃与恢复 | 写入中断、外部不可逆副作用与收据丢失的 Unknown/人工协调 | **未验证** |
| 多 Agent/跨平台 | 分布式工作区、Windows/macOS 隔离、参考内核动态跑分 | **未验证** |

**决策**：保留现有经过验证的只读 Host、Kernel Loop 和 EventJournal；将生产写入能力保持关闭。优先实现专用 Workspace Host 的可信控制接口和隔离执行协议，然后在同一链路上跑真实补丁及测试，不再把 RO 子目录直接升级为“安全写工具”。
