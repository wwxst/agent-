# 自研 Agent Kernel：四套内核的机制对照与候选取舍

> 版本：研究草案 2026-10-25。**这是基于源码的首轮工程取舍，不是最终接受的 ADR 或 Benchmark 排名。** 所有比较均限于 [证据登记](00-研究方法与证据登记.md) 锁定的特定源码，不涉及模型效果分数。

## 一、先明确“要造什么”，避免把参考项目拼起来

目标是自主实现**第五套** Kernel。Pi、Codex、Claude Code、DeepSeek Harness 是研究对象；不以任何一个运行时作为核心执行依赖。

我们的内核职责：`Session/Turn/Step` 状态机、Provider 规范化、Context Admission、ToolCall Lifecycle、Policy/Approval、可恢复 Event Journal、Resource Scheduler、Subagent、Cancellation、公开协议。

与之解耦的能力：LLM Provider、实际 Tool Host/Sandbox、MCP/Skill/Hook、GUI/CLI、领域执行器、持久化 Backend。

## 二、源码证据支持的架构对照

| 维度 | Pi | Codex | Claude Code | DeepSeek Harness | 我们的取舍 |
| --- | --- | --- | --- | --- | --- |
| Loop | TS 双层循环、Callback 显式 | Rust Session/Turn/采样 Step | CLI Generator `YL/su/iu` | `ReactLoopAgent` Turn/Step | **Pi 式可读 Loop，Codex/DS 式明确状态** |
| 输入插队 | Steering / FollowUp 队列 | Session input_queue / pending_input | SDK/CLI Steering/Task 控制 | 持久 Inbox、next-step/turn | **区分 steer/followup/queue/cancel** |
| 模型抽象 | `StreamFn` | ModelClientSession/ResponseItem | CLI 模型请求及流事件 | `ctx.llm` Adapter | **标准 Provider 接口，不绑定模型** |
| 工具调度 | 整批并行/串行、顺序 Preflight | ToolRouter + Registry 并发声明 | 流式入队、`isConcurrencySafe` | 独占屏障 + 并发数限额 | **流式感知 + 完整调用后执行 + 资源冲突图** |
| 工具可见与可执行 | tools 快照/差异声明 | Spec vs Runtime ToolRouter | 工具名称解析、Schema/权限 | Scoped Registry + Step resolve | **入场快照冻结 ToolSet 版本** |
| 权限 | Core Hook，宿主补强 | ApprovalAction/Guardian + Sandbox | Hook、Policy、审批与多平台沙箱 | Guard、Approval、Executor 插件 | **可信 Policy 根 + OS Tool Host 双重校验** |
| 会话事实来源 | 进程内 transcript/事件（Core） | ThreadStore/Rollout/Session | Transcript/存储与恢复逻辑 | Session Event + 投影 + flush | **持久事实日志 + 快照，不把 UI 事件当事实** |
| 崩溃恢复 | Core 非完整持久内核 | 线程存储抽象/恢复 | 子 Agent/Session 回放（细节待实测） | write handle + interruptedClosers | **Durable Intent + Host Receipt + OutcomeUnknown** |
| 上下文压缩 | transformContext/prepareRequest seam | pre/mid-turn compaction | auto/reactive compact、失败策略 | 历史派生/压缩插件 | **Checkpoint 化压缩，事实不进摘要权威** |
| 多 Agent | 上层可组织 | 公开组件存在子任务能力 | AgentTool、Fork/Resume | Scope/Agent Teams | **子任务是独立生命周期 + 减权** |
| 扩展 | 轻量 Callback/工具 | Plugin/Tool Registry | Hooks、Skills、MCP | Cordis/Profile/Bundle/ScopedLayers | **DS 式能力组合，但不热替换信任根** |
| 客户端 | 由宿主包装 | App Server/协议 | SDK ProcessTransport/stream-json | Profile/Web/SDK | **自有版本化 API + 事件重放** |

这不是安全性/性能名次表。某项目在某包中没有某功能，不代表它的整个产品完全缺失。

## 三、我们真正应该拿走的机制，而不是源码

### A. Pi 提供“可理解的执行器”

- 小型 Kernel Loop，模型流与执行逻辑明确。
- 硬错误、截断 ToolCall、Steering、FollowUp 各有明确处理。
- 工具先完整预处理和校验，再执行。
- 每次 ToolCall/Model Message 都通过结构化事件回到宿主。

**不要照搬**：把 in-memory transcript 当唯一事实来源；全局 `abort()` 宣称撤销所有外部副作用；把 Hook 的 allow 直接当 OS 授权。

### B. Codex 提供“执行事实的工程边界”

- Session/Turn/Step、StepContext 与工具集合固定；
- ToolRouter 规范化模型调用、ApprovalAction 与 Sandbox Policy 分开；
- Rollout、ThreadStore/LiveThread 将历史记录、元数据和运行中的状态拆分；
- CancellationToken 明确传播，但真实回执和外部副作用必须再核验。

**不要照搬**：特定 OpenAI ResponseItem、Rust 巨型项目的包层级、全部 Guardian/Product 规则或内置工具集。

### C. Claude Code 提供“真实交互和长时工具的细节”

- StreamingToolExecutor 在 assistant tool_use 到达后尽早入队、同时区分并发；
- 权限/Hook/SDK Control Request 有明确运行层次与竞态；
- Context Compaction 不是只摘要一次；
- Subagent、Fork、后台 Shell、Resume 具有产品级异常路径；
- 新版确实具有 Windows `wrapWithSandboxArgv` 和 Desktop SDK ProcessTransport。

**不要照搬**：通过打包符号复原原始 TS 类结构；模型不可见输入之外还允许不可信调用伪造内部特权字段；将 `interrupt`/进程退出误认成外部工具完成。

### D. DeepSeek Harness 提供“组合能力和日志投影”

- Cordis 的 Scoped Service/工具注册与资源所有权；
- Session Event 派生模型历史、Inbox/Agent/Step 分层；
- 并发工具的独占屏障、顺序提交、合成 ToolResult；
- Persistence Handle 单写、append 与 flush 不同保证；
- 恢复时对未结束的 Turn 做显式语义闭合。

**不要照搬**：根运行时所有职责均可热替换、关闭时 `turn/end` 尚未持久化的缺口、无内建 Turn 预算，或者把一次语义补齐当做外部副作用已确认未执行。

## 四、推荐的自主架构（仍需 ADR 接受）

```text
Web / CLI / Desktop / Automation
         │  Commands + Event Stream (自有 v1)
         ▼
┌──────────────────────────────────────────────────────┐
│                 Trusted Agent Kernel                │
│  Session/Turn/Step FSM   Durable Event Journal      │
│  StepAdmission           Budget + Context Manager  │
│  ToolCall Scheduler      Policy/Approval Root       │
│  Cancel/Interrupt        Child Task Coordinator     │
└──────────┬──────────────┬───────────────┬────────────┘
           │              │               │
       Model API      Capability       Tool Host
       Providers      Composer         (OS Sandbox)
                      Scope/Profile     Worker Receipt
           │              │               │
      OpenAI/DeepSeek   MCP/Skills     File/Shell/Browser/Media
      Claude/local     Hooks/Tools
```

### 内核必须守住的五个权威

1. **Session/Turn/Step 状态转移权**只在可信 Kernel，普通插件不能写任意终态。
2. **审批授权根**只在可信 Policy，模型文本、第三方 Skill 和 Hook 没有增权权力。
3. **副作用是否发生的证据权**在 Tool Host/收据；ToolResult 文本和自然语言说明不能代替。
4. **历史事实的提交权**在 EventStore/事务，UI 只读并回放；Snapshot 只是可重建派生视图。
5. **预算和取消的硬限制权**在 Kernel/Host，不允许特定 Provider 或 Plugin 将其彻底关闭。

### 可以自由组合的五类能力

- Provider Adapter（模型、上下文窗口、推理与多模态能力）
- Tool Adapter/Tool Host（执行任务，必须持有能力许可）
- Context Contributors、Skills 与项目规则（均有来源、可信度和 Token 限额）
- Subagent Task Definition（权限是父能力的子集，控制深度/并发/预算）
- Client Transport、Domain Workflow、Profile（可卸载，不能绕过内核）

## 五、协议与状态机应该如何定义

### User Turn 与 Model Step

```text
Session
  Turn[id, expectedStateVersion]
    Step #1: context → provider response → tool batch
    Step #2: tool results → provider response → complete
```

User Turn 可以包含多个 Model Step。Pi 的 `turn_end` 是一条 assistant 响应结束，Codex/DS 的 Turn 语义在其版本里有所不同，因此**必须定义自己的类型，不直接取一个项目的术语当通用事实**。

### 工具执行状态

```text
proposed
   → validated
   → policy_checked
   → approval_pending (可选)
   → intent_committed (持久化)
   → isolation_established
   → running
   → succeeded / failed / outcome_unknown
```

必要不变量：

- ToolCall 参数完整并通过 Schema 才能进行 preflight。
- 不能依赖模型自己为危险操作授权。
- 即使客户端断线也应能按 ToolCall ID 查询 Host 执行收据。
- 未确定结果的非幂等操作不能重试。
- 重放工具结果是恢复模型上下文，不等于再次实际运行工具。

### 事件双轨

- **Durable**：Turn/Step、UserMessageAccepted、ToolPrepared、Approval、ExecutionReceipt、ToolResult、ContextCheckpoint、SessionTerminal。
- **Ephemeral**：Token delta、临时进度、UI 载入/思考提示。
- 持久事件先提交，再广播；不可把插件实时通知的完成当作已持久化。
- Context Compaction 仅产生新视图/检查点，不覆写原始事实。

## 六、阶段取舍，不被“全都要”绑架

| 阶段 | 必须先有 | 延后 |
| --- | --- | --- |
| M0 | 类型、状态不变量、FakeProvider、FakeHost、MemoryEventStore、最小 Tool Registry、错误码 | 插件运行时、真实 Shell |
| M1 | 自研 Loop、Steering/FollowUp、两 Provider 兼容协议、工具校验/顺序与并发测试 | Subagent、复杂媒体 |
| M2 | 持久化/重放、审批、Sandbox Host、Crash Recovery、Context 压缩检查点 | 热插拔一切 |
| M3 | Scope/Capability、Skills、MCP、Subagent、异步后台任务 | 任意分布式任务 |
| M4 | Remote Worker、Media/Browser ToolHost、领域工作流、性能优化 | 不受控插件升权 |

## 七、尚不能最终定案的取舍

以下必须等 [验证计划](06-未完成事项与验证计划.md) 的证据再决定：

- 具体语言：TS 单进程 vs TS Kernel + Rust ToolHost；不能凭“Rust 更安全”就选 Rust；
- 数据库存储：SQLite/JSONL、PostgreSQL、消息队列组合的故障保证；
- 并发策略：一元安全+独占屏障 vs 资源冲突图；需要测冲突正确率和复杂度；
- 上下文摘要：本地/远程压缩以及保留关键事实的方法；
- Subagent Fork/隔离：是共享父 Session 历史前缀，还是复制投影 / 引用旧日志；
- Desktop IPC：用自己协议还是针对现有客户端 Adapter；需审阅 agent-web 与 agent-cil 的真实接口。
- 沙箱：Linux/macOS/Windows 使用何种真正可验证的 OS 能力。

## 补充：2026-10-25 后续源码深研对候选方案的影响

- **Pi 不能仅用低层 Agent Core 的内存 transcript 评价**：Coding Agent 产品层确有独立 JSONL SessionManager、树状 Fork/Branch、Context Edit 和压缩切点；参见 [07](07-Pi-Coding-Agent-上层会话扩展与Shell.md)。
- **Codex 的回写比“有 ThreadStore”更明确**：App Server 的 Steer 带 expectedTurnId，普通 Interrupt RPC 可以等待 TurnAborted；LocalWriter 写入后 Flush，再投影 SQLite；参见 [08](08-Codex-AppServer-指令审批与持久化屏障.md)。这仍不直接证明任意外部副作用的 exactly-once。
- **DeepSeek 的工具安全/执行机制更具体**：Native/PTC 共用 PreExecute/Approval/Guard/Dispatch/Complete Pipeline；PTC 的 run_code 有隔离/提权能力要求及嵌套调用收据；参见 [09](09-DeepSeek-工具执行管线与PTC隔离.md)。内存 Session append 仍不等于持久 flush。
- **Claude Desktop 新版可以直接读到更多 SDK 细节**：子进程参数、控制请求的去重缓存、进程退出分类和 senderFrame 校验；但 UI→具体 IPC Channel→Session 所有权的链条仍未完成；参见 [10](10-Claude-Desktop-SDK-进程控制与错误边界.md)。

四套方案的对照进一步凝练为 [12 条不变量与架构评审门槛](11-跨内核不变量与架构评审门槛.md)。**选型仍须由实际故障注入和 ADR 决策确认。**

## 八、总体取舍结论（暂定）

**核心逻辑取 Pi 的可理解性；执行可靠性与审批边界取 Codex；长时工具/子 Agent/交互异常路径取 Claude Code；能力组合/Scope/事件投影取 DeepSeek Harness。**

这个结论是**参考机制分工**，不是四个项目源码拼接，也不是权威性能排名。需要用自研原型的 Test Matrix 反复推翻/验证；尤其不要把研究取舍写成已经接受的 ADR。
