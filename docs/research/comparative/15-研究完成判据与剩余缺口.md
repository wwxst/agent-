## 2. “完成”不是一个没有范围的形容词

本项目对每套/每个具体版本使用四级标签：

- **S1 静态存在确认**：函数、关键类型、主要调用者与副作用入口定位，附版本和行号/模块哈希；
- **S2 机制分支复原**：正常、失败、Abort、Retry、Steer、Resume 等路径有完整状态图，确认所有安全边界与调用条件；
- **S3 单实例动态复核**：本地可复现运行，记录参数/平台、退出码、事件序列和结果；对危险 Sandbox 做隔离测试；
- **S4 故障/跨平台复核**：kill/断电窗口、Tool Host 收据丢失、HTTP 重放、多 Worker Epoch 与不同 OS 沙箱行为已验证。

**本轮达到的级别是多个核心子系统 S1、部分 S2。没有完成 S3/S4，因此不应写“已完全研究透”。** 公开仓库源码也无法证明闭源远程模型和服务端的所有状态。

## 4. 仍需逐套收尾的硬问题

### Claude Code

- Desktop Renderer → **具体** IPC Channel → Main Process Session Owner → Agent SDK → CLI 的全路径调用点；
- CLI 2.1.304 Session 持久化、后台 Subagent、Fork/Resume 与用户旧版不同之处；
- 多 Feature Gate 下 Permission/PreToolUse 顺序；Windows/macOS/Linux 的 OS 隔离边界；
- ToolCall 意图/实际 Shell/工具结果写盘交错时产生未知状态的确切窗口。

**阻碍**：本次运行环境无法重新解开完整 ZIP，因此不能把旧版每个分支当成新版已复核；以前的 A1 证据维持原样，不虚构新增偏移。模型远端能力不可见。

### Pi

- Extension 载入/热重载与系统 Shell 自定义 Executor 在不同 API 入口下的能力范围；
- SessionManager 第一次文件创建、追加、Context Edit、Compaction 在写盘失败后的恢复一致性；
- 进程树 Kill 的真实跨平台保证与扩展来源安全；
- Coding Agent 更多与 MCP/远程模型/子代理相关的功能、测试和完整失败分支。

### Codex

- `RolloutRecorder.flush()` 之外有没有配置特有的 fsync/严格磁盘同步路径；
- App Server 终态消息广播与 Rollout 记录先后顺序；多进程重入；
- Approval/Sandbox/Guardian Feature Gates 的全部组合；
- 多 Agent、后台目标与线程 Fork 的完整事实结构及外部副作用收据。

### DeepSeek

- Live Session 异步批处理在 Root shutdown、后端断联期间的真实写入损失边界；
- 当前 JSONL 后端普通 Append 在各平台的物理持久化细节与断电行为；
- Guard、Approval、Native/PTC 与 PtcRuntime 组合的真实权限范围；
- Cordis Scope 卸载、Agent Team、嵌套工具运行中的 Context 泄露与并发恢复边界。

## 6. 自研取舍可以先做什么，哪些要等测试

### 可先作为 M0 的工程方向

- 自己实现小型 Turn/Step FSM，不以任何参考运行时为依赖；
- 模型输出必须完整 Schema 验证，工具准入/回填可确定性测试；
- 只读工具并发与独占工具串行，结果严格配对；
- EventJournal/工具收据分离，Snapshot/摘要没有事实权威；
- 子任务减权、权限 Deny Root、Hook 不得提升执行权限。

### 必须经过动态实证再接受为安全保证

- 具体 SQLite WAL 同步、断电重启与 OS 文件系统的持久性；
- 任一平台的实际 Shell Sandbox、符号链接/重解析点/权限逃逸；
- Cancel/Timeout、后代进程、外部 API 的副作用收敛；
- Subagent 后台跨进程恢复和 Worker Epoch Fencing；
- 相同模型/工具/预算的性能对照。

**审计结论**：目前已能把四家主要内核机制拆解得较清楚，可以明确推荐自研架构；但还不能在严格工程意义上声称四套全部完成 S4。把未知问题显式记录、固定接口/测试标准，比制造虚假的“100% 研究完成”更有价值。
