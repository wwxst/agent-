# 13 · 四内核 ToolCall、权限、并发、Cancel 与异常恢复对照

> 审阅日期 2026-10-26。此文是**函数/状态层的静态比较**，不是性能排名、实际 OS 沙箱安全认证或运行测试。对象与固定提交详见 [00 证据登记](00-研究方法与证据登记.md)。

## 1. 执行循环和“何时能执行模型建议的工具”

| 内核 | 具体源码调用点 | 已确认条件 | 不能想当然 |
| --- | --- | --- | --- |
| Pi | [agent-loop.ts](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/agent/src/agent-loop.ts#L250-L315) | Model StopReason=length 时不执行被截断消息中的 ToolCall；工具经 `prepareToolCall` 才进入执行 | 流式输出的 JSON 片段不是批准执行的完整参数 |
| Codex | [tools/router.rs](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/core/src/tools/router.rs#L257-L394) | ResponseItem 被规范化为带 call_id、Session、StepContext 的 ToolInvocation；Runtime 按注册表执行 | “模型看得到工具”并不等于有 OS 权限 |
| Claude Code | [2.1.304 新版实证记录](01-Claude-Code-2.1.304-新版复核.md) | 打包 JS 中能看到完整 `tool_use` 到 StreamingToolExecutor，再到权限、Tool `call` 和 `tool_result` 的链路 | 新版不同模型/Feature Gate 分支仍需动态复核 |

共性：**ToolCall 需要有稳定身份、完整参数、可复核的权限结果，不能在流式片段尚不完整时开始副作用。**

## 2. 谁允许，谁有权否决

### Pi：Hook 是产品扩展点

[ExtensionRunner](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/extensions/runner.ts#L1190-L1265) 的 `tool_call` 可拦截/Block；`tool_result` 可以修改 `isError/content/details/usage`。这适用于可定制的工具体验，但并非稳定的 Host Receipt。操作系统访问控制仍应在进程/文件权限边界执行。

### Codex：策略前置和审核来源标注

[approvals.rs](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/core/src/tools/approvals.rs#L465-L580) 某些 sandbox override 场景先受 Policy 拒绝；随后 `run_permission_request_hooks` 可能给出 Allow/Deny，缺省转入 Guardian/用户 Reviewer。最终 `ApprovalResolutionSource` 被记录。**本链上的 Hook 决策不等于全部系统层限制被解除**。

### Claude Code：PreToolUse、Policy、SDK 宿主审批多层叠加

先前 [12 旧版权限追踪](../claude-code/12-权限审批与沙箱.md)、[17 SDK 审批竞态](../claude-code/17-SDK控制协议与审批竞态.md) 已定位 2.1.88 的 Hook/SDK 并发，以及工具安全校验与 deny/ask/allow。新版打包 JS 也能定位权限执行入口，但无法据旧版所有默认值推定新版每个平台的最终结果。

### DeepSeek：显式 “Allow 之后仍检查 Guard”

[ToolExecutionPipeline.prepare](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/core/tools/src/pipeline.ts#L185-L245)：
`pre-execute` 返回 allow/deny/ask → 若 ask 则调用 Approval 服务 → **只有 allow 才执行 checkGuards** → deny 生成规范 ToolResult。Guard 是最终否决层，而不是只给模型再说一遍“不要”。

**自研取舍**：不直接复制任一家“Hook 决策优先级”。应定义可信 `PolicyRoot`：
- 规则型 HardDeny 永远不可被扩展覆盖；
- Hook/自动审核只能影响 Ask/DecisionProposal，改变参数必须重新授权；
- Host 以 `toolCallId + argsHash + policyVersion + hostId + expiry` 核查最终授权；
- 用户 UI 的“批准”只是输入，不是由 Renderer 直接签发执行能力。

## 3. 并发调度：至少三种不可等同的方案

| 项目 | 真实策略 | 保证/代价 |
| --- | --- | --- |
| Pi Core | [执行器](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/agent/src/agent-loop.ts#L518-L690) 遇 `sequential` 则整批串行，否则先按原序 Preflight，再 `Promise.all` | 易读、易测；可能不必要地整体串行 |
| Claude Code | 新版 [StreamingToolExecutor](01-Claude-Code-2.1.304-新版复核.md) 在工具可完整入队后根据 `isConcurrencySafe` 调度 | 工具可与模型流重叠；时序与权限须认真审计 |
| DeepSeek | [batch.ts](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/core/tools/src/batch.ts#L110-L269)：独占屏障+最大并行数；只有 body 重叠，preflight/post-execute/commit 按序 | 吞吐与历史因果顺序兼顾；资源冲突仍依赖一元分类 |
| Codex | [ToolRouter](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/core/src/tools/router.rs#L246-L395) 向 Registry 查询是否支持 parallel，ToolInvocation 带 StepContext | 注册的并发属性并不自动提供资源写集/文件锁 |

**推荐自研 S2 基线**：独占屏障 + 只读工具并发 + 原序 ToolResult 提交；分类未知→独占，且正式放权前 Host 必须做最终路径/网络检查。第二阶段才评估按读写集构建冲突图（S3）。

## 4. 取消与中断：不同对象不能共享一个 boolean

- **Pi**：[tools/bash.ts](https://github.com/earendil-works/pi/blob/d5b3de22d0e24a3e9c38a9410d3329b099717283/packages/coding-agent/src/core/tools/bash.ts#L97-L169) 的 Abort/Timeout 尝试 `killProcessTree`，并根据 signal/timeout/退出码归类；不能证明所有后代网络请求均被撤销。
- **Codex**：[App Server turn_interrupt](https://github.com/openai/codex/blob/970111f6cb62cc02fe36a82ea7d71b37a2889c97/codex-rs/app-server/src/request_processors/turn_processor.rs#L1622-L1685) 普通 Turn Interrupt 可将请求挂起直到 `TurnAborted`；Startup Interrupt 特殊处理。Steer 另要求 `expectedTurnId`，且 Review/Compact Turn 有不可 Steer 的拒绝路径。
- **Claude Code**：2.1.88 [ShellCommand](../claude-code/19-Shell实际执行与取消语义.md) 中 `interrupt` 原因可使 Shell 继续转后台，非 interrupt Abort 则尝试 kill；最新版需要重新确认具体开关。
- **DeepSeek**：[ToolExecutionPipeline](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/core/tools/src/pipeline.ts#L270-L330) 对已开始的 Body 等待 settle 再生成取消语义；[batch.ts](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/core/tools/src/batch.ts#L110-L240) 取消时不再启动未执行调用、对余下产生合成结果。

**共同陷阱**：“发了 Cancel”“发了 SIGKILL”“UI 收到工具取消结果”三个事实都不能单独证明外部世界未受影响。

### 自研取消状态表

| 输入 | Kernel 立即承认 | 最终状态依据 |
| --- | --- | --- |
| interrupt(turnId) | 记录 InterruptRequested | Model/Turn 中断事件 + 工具状态收据 |
| cancel(turnId) | 记录 CancelRequested | Host 是否完成/被杀/结果未知 |
| stopTask(taskId) | 记录 StopRequested | 子任务 Worker 收据 |
| timeout(toolCallId) | 记录 DeadlineExceeded | 若无法确认已停止副作用，`OutcomeUnknown` |
| steer(expectedTurnId,message) | 检查版本与 Step Admission | 成功入队，否则拒绝 |

## 5. OS 隔离和权限范围

| 项目 | 可直接确认 | 尚不能声明 |
| --- | --- | --- |
| Pi | Coding Agent Shell 以 `child_process.spawn` 运行，本路径 cwd 缺失就拒绝 | 整个产品具有统一强制 OS 沙箱 |
| Codex | Rust 有 Tool Sandbox 与 Linux Bubblewrap 的单独实现，WSL1 有限制 | 所有任务/工具/平台天然防越权 |
| Claude Code | 2.1.304 有 Windows `wrapWithSandboxArgv` 的平台分支及 POSIX 包装路径 | 所有 CLI 调用都强制沙箱且隔离完全无漏洞 |
| DeepSeek | [PTC](09-DeepSeek-工具执行管线与PTC隔离.md) 根据 Runtime/SandboxPolicy 要求、提权 Approval 运行，并报告 full/partial | 任意 PTC Runtime 的 OS 强制隔离已经独立测试通过 |

我们的 Tool Host 必须返回**实际隔离证据及能力缺失报告**，不能以插件声明或 UI 徽章代替系统执行。

## 6. 数据事实与重放规则

- Pi 的扩展能修改 `isError`，因此 HostReceipt 必须独立于模型可见 ToolResult；
- Codex `RolloutRecorder.flush()` 从已审路径无法证明 fsync，详见 [12 持久化证据审计](12-四内核执行与持久化证据审计.md)；
- DeepSeek `session.append` 实时投影与 `SessionHandle.append` 的持久时序不同，恢复时合成中断结果不等于外部操作没发生；
- Claude Code 的 Transcript 恢复不等于分布式精确一次操作保证。

**研究结论**：最有工程价值的不是复制某个 Tool Executor，而是将 **ToolCallAdmission / TrustedPolicy / HostExecution / ReceiptJournal / ModelResultProjection** 明确拆开。
