# 14 · 自研 Agent Kernel 架构取舍：正式技术评审稿

> 日期：2026-10-26。性质：**历史推荐稿（Recommended / Proposed），目前不具备冻结效力**；不是维护者接受的最终 ADR，也不是已实现代码。2026-10-29 起按 [26 号架构重评](26-架构重评第一轮-2026-10-29.md) 重新评估，且重新打开“是否还需要自研第五套内核”的上游决策；在 Issue #42 完成前，不应把本稿的技术推荐视为不可变的实施标准。四套内核证据见 [00](00-研究方法与证据登记.md)、[12](12-四内核执行与持久化证据审计.md)、[13](13-工具权限与异常恢复对照.md) 和各专题报告阅读。

## 0. 最终目标与不做的事

构建的是**第五套自研 Agent Kernel**，可服务 CLI、桌面、Web、API，不要求用户先安装 Pi/Codex/Claude/DeepSeek Harness 中任何一套运行时。

Kernel 必须有稳定的独立职责：Session/Turn/Step、模型流规范化、上下文预算、工具入场/调度、可信授权、持久命令/事件、取消、子任务和恢复。

**不做**：第三方源码拼接；在生产中包装 Claude CLI 作为内核；把模型评分等同于 Harness 评分；声明“工具永远 exactly-once”；将未经安全验证的脚本直接以当前用户身份无限制执行。

## 1. 核心决策与主要替代方案

| 议题 | 本次明确推荐 | 为什么不是其他方案 | 何时复审 |
| --- | --- | --- | --- |
| Kernel 编程语言 | **TypeScript/Node，严格 TS + Runtime Schema**（M0–M2） | Pi/DeepSeek 的规范化接口容易在 TS 下验证；直接照搬 Codex Rust Core 太重；但 TS 不提供 OS 隔离 | 宿主安全/吞吐测试证明 TS 是瓶颈时，再考虑 Rust 原生 Host |
| 状态模型 | **Session → UserTurn → ModelStep → ToolCall**，有持久单调版本 | Pi `turn_end`、Codex Turn、DS Turn 不完全同义，必须自定义稳定术语 | 自研协议初版评审 |
| Loop | **Pi 式小型可测循环** + Codex 的 StepAdmission 快照 | 避免 Claude 一体化巨型循环；防工具热重载导致模型工具视图与宿主不一致 | K01/K16/K17 |
| 工具调度 | **S2：只读并发 + 独占屏障 + 原调用顺序提交** | Pi 全批串行保守但可能浪费并行；S3 资源冲突图初期太难保证 | S1/S2 基准和安全测试后可升级 S3 |
| 工具隔离 | **独立 Tool Host 进程/OS 隔离，安全 Policy 双重核查** | “工具插件自己声明安全”不是隔离；无已验证沙箱时不开放高危 Shell | 各 OS 单独通过逃逸与子进程测试 |
| 持久化 | **SQLite WAL 事务型权威 Event Journal（本地首版）** | 普通 JSONL 便于审阅，但原子接受命令/审批/事件/去重更容易用事务型存储做正确；第三方 Flush 实现不等于自己的掉电保证 | 压测、SQLite 故障注入和跨进程写入验证 |
| 可查询索引 | 初版同库投影表；后续分离可重建索引 | Codex 的 Rollout+SQLite 适合已有复杂历史；我们 MVP 先简化一份权威库 | 导出、备份、查询性能后评估 |
| Context | **预算 Admission + Checkpoint 摘要 + 不可变原始事实** | 不把摘要当事实，不复制某个模型/版本的 Token 阈值 | 小窗口/压缩失败测试 |
| 扩展 | **Scope 化 Provider/Tools/Skills/MCP，Provider 版本与撤销** | 借 DS 的组合能力，但 FSM、Policy Root、EventStore Commit 不可热替换 | Plugin 生命周期 K17 |
| Subagent | **Task Tree、独立 Context、减权、独立预算和收据** | Claude 旧版特殊继承逻辑未必严格减权；自研明确默认子集 | M3 之后 |
| 传输协议 | **独立版本化 Commands + Durable SSE Events**（stdio/WS Adapter） | Claude SDK/CLI Control 协议是参考，不作为自研公共 ABI；实时 Delta 不应假充事件事实 | 客户端协议兼容测试 |

这张表已**作出具体工程取舍**；但每个高风险项带回归测试门槛。推荐不代表实现完成或工程性能已被实测。

## 2. 参考项目分别贡献什么

### Codex → Step 一致性 + Policy/Storage 工程边界

### Claude Code → 流式工具 + 交互、长期任务、Subagent

**放弃**：用打包 JS 的压缩符号作为稳定 SDK、无证据声称所有平台默认沙箱、把 `interrupt` 当所有子任务都已停止。最新版 Desktop UI 全部 IPC 仍未打通。

### DeepSeek Harness → Scoped 组合 + Guard + 事件模型

从 [04](04-DeepSeek-Harness-源码研究.md) 借 Scope、Registry、Event Projection/Inbox；从 [09](09-DeepSeek-工具执行管线与PTC隔离.md) 借 PreExecute/Ask/Guard、并发体与有序提交、PTC 的隔离能力校验。

**放弃**：把 Session 内存 `append()` 当强持久化；允许普通插件替换 PolicyRoot 和 Store Commit；没有内建 Turn Budget 的行为；把合成“interrupted”视作外部工具未运行证明。

## 3. 候选可信架构

```text
Clients: CLI | Desktop | Web | SDK
     │
     │ Commands (idempotencyKey, expectedVersion)
     ▼
┌──────────────────────── Trusted Kernel ─────────────────────────┐
│ Command Admission / Durable Inbox / Session Turn FSM            │
│ StepAdmission (provider/toolset/policy/context snapshot)        │
│ Provider-normalized Stream + Context Budget & Checkpoint        │
│ Tool Scheduler (safe reads parallel + exclusive barriers)       │
│ PolicyRoot / ApprovalDecision Store / Task Coordinator          │
│ Durable Event Journal + Snapshot / Outbox + Receipt Reconciler  │
└──────────────┬──────────────────────┬────────────────────────────┘
               │                      │
         Scoped Providers       Verified ToolHost
         Skills / MCP           OS isolation / actual receipts
               │                      │
         LLM providers          File / Shell / Network / Browser
                                      │
                              External side effects
```

严格区分三类存储：

- **事实（Authority）**：命令接受、审批、Tool Intent、Host Receipt、Turn/Task 状态、预算消费；只有可信服务端可以事务提交。
- **投影（Projection）**：模型历史/摘要、会话树、搜索索引、UI Snapshot；可以重建，不能反向给业务事实提权。
- **实时（Ephemeral）**：token delta、进度动画、部分模型流；没有持久恢复承诺。

## 4. v0.1 接口合同（独立自主定义）

```ts
type SessionId = string;
type TurnId = string;
type StepId = string;
type ToolCallId = string;

type ToolOutcome =
  | { kind: 'succeeded'; receiptId: string; artifactIds: string[] }
  | { kind: 'failed'; receiptId: string; errorCode: string }
  | { kind: 'outcome_unknown'; reason: string; hostId?: string };

type StepAdmission = {
  stepId: StepId;
  turnId: TurnId;
  expectedSessionVersion: number;
  providerId: string;
  providerVersion: string;
  toolSetVersion: string;
  policyVersion: string;
  contextCheckpointId: string;
  budgetReservationId: string;
};

type ToolCallIntent = {
  toolCallId: ToolCallId;
  stepId: StepId;
  toolName: string;
  toolVersion: string;
  canonicalArgsHash: string;
  approvalDecisionId?: string;
  hostId: string;
  isolationRequirementId: string;
  idempotencyClass: 'pure' | 'idempotent' | 'non_idempotent' | 'unknown';
};

type ModelFacingToolResult = {
  toolCallId: ToolCallId;
  content: unknown;
  isError: boolean;
  sourceReceiptId?: string;
};

type DurableEvent = {
  eventId: string;
  sessionId: SessionId;
  seq: number;
  schemaVersion: number;
  at: string;
  kind: string;
  payload: unknown;
};
```

**不变量**：
1. `StepAdmission` 固定本轮模型、工具、Policy、上下文和预算版本；
2. ToolHost 接到的请求必须与已持久 ToolCallIntent + ApprovalDecisionId 一致；
3. 模型历史可处理/截断/重写 ToolResult，但 `ToolOutcome` 不可篡改；
4. 单个 ToolCall 的 Host 执行不会因 Agent Context 重放再次触发；
5. 应答 `CommandAccepted` 前已提交对应命令的持久状态。

## 5. 最小持久化方案（供 ADR 决策）

**推荐 SQLite WAL**，单主写者。建议表：

| 表 | 事实/用途 | 约束 |
| --- | --- | --- |
| `sessions` | id、version、状态 | CAS 版本更新 |
| `commands` | idempotencyKey、actor、Command、acceptedSeq | `(sessionId,idempotencyKey)` 唯一 |
| `events` | eventId、sessionId、seq、kind、payload | `(sessionId,seq)` 唯一，终态不可覆写 |
| `tool_intents` | toolCallId、argsHash、approval、Host、idempotencyClass | ID 唯一且不可变 |
| `tool_receipts` | toolCallId、Host sequence、outcome、artifactRefs | Host 签名/会话授权核验 |
| `approvals` | decisionId、toolCallId、scope、validUntil | 已决不可回退 |
| `snapshots` | projectionVersion、lastSeq、Context | 可以重建 |
| `outbox` | eventId、broadcast/notification cursor | 与事件同事务写入 |

推荐基线：`PRAGMA journal_mode=WAL`、对关键事件使用严格同步配置（例如 `synchronous=FULL`），并进行 kill/异常写盘/掉电能力测试。**没有测试时，连 SQLite WAL+FULL 也不宣称跨所有文件系统/磁盘保证绝对耐久**。

事件日志可导出 JSONL（便于 Debug/Interop），但权威日志只定义一种；远程多 Worker/多地域时重新评估 Postgres/Lease，而不是在 v0.1 同时上复杂分布式一致性协议。

## 6. API 和执行入场

```text
POST /v1/sessions             创建 Session
POST /v1/sessions/{id}/turns  接受 Turn（必须有 idempotencyKey）
POST /v1/sessions/{id}/steer  expectedTurnId；版本不匹配→冲突
POST /v1/sessions/{id}/cancel expectedTurnId + cancelToken
POST /v1/approvals/{id}       只提交特定 ToolCall 的决策
GET  /v1/sessions/{id}/events?after=<seq>  SSE 持久事件重放
GET  /v1/tasks/{id}          查询长时子任务与结果未知状态
```

模型 Token Delta 走单独可丢实时流；SSE 里的终态从权威事件存储重放，不能凭前端的“流结束了”推断任务成功。Client 可以断线恢复，不能用网络重试重新执行 ToolCall。

## 7. 复杂度递增顺序

| 里程碑 | 落地代码 | 必须通过 |
| --- | --- | --- |
| M0 | `contracts`、纯 FSM、FakeProvider、FakeHost、MemoryStore、确定性模拟时钟 | 断流/重复 ID/合法转移属性测试 |
| M1 | TS 自主 Loop、StepAdmission、Native Tool Registry、S2 调度、Steer/FollowUp、硬预算 | 工具参数完整才执行、结果有序、Cancel 不假成功 |
| M2 | SQLite EventStore、ApprovalRoot、独立 ToolHost、持久 Intent/Receipt、Crash Recover、Checkpoint | K01–K18 中与本阶段相关全部测试；非幂等 Unknown 不重试 |
| M3 | Scope、Skills、MCP、Subagent Task Tree、后台任务、可逆插件资源 | 严格减权、热卸载 Drain、跨 Scope 无权限泄露 |
| M4 | Remote Workers、Browser/Media Host、跨平台强沙箱、可观测和基准优化 | 旧 Epoch 不能执行、跨主机收据/隔离验收 |

**M0/M1 不建议执行任意高危 Shell**。尚无经过验证的 OS Sandbox 时，只允许 FakeHost/受限只读工具，危险工具保持关闭或明确隔离后再引入。

## 8. 还必须通过的设计评审问题

- TS Kernel 与独立 ToolHost 通信的 IPC 及签收协议；
- SQLite 事件 + ToolHost 原子性**不可能跨不受控外部系统实现无条件原子提交**；必须明确 OutcomeUnknown；
- Provider 多模态/模型能力与预算如何协商，而不把 Token 估算作为精确认证；
- Tool Scheduler 对动态资源锁的可观测性和成本；
- Parent/Child 同步审批与后台审批的 UX；
- 具体 OS Sandbox 的支持矩阵、权限不足时如何拒绝而非自动降级；
- 客户端和插件版本迁移、事件 Schema 兼容性与重放。

## 9. 评审结论

**推荐作为自研实现起点**：

- **选 TypeScript + SQLite WAL + 独立 ToolHost** 作为 v0.1 原型技术路线；
- Loop 取 Pi 简洁，状态/安全参考 Codex，工具和长任务吸收 Claude，Scope/Guard/事件模型吸收 DeepSeek；
- 调度从 **S2 保守并发 + 独占屏障** 开始，明确最后的安全否决权；
- 所有真实副作用有 Durable Intent、Host Receipt 与 OutcomeUnknown；
- 文档及 ADR 现在是**推荐提案**，只有通过 [15 验收清单](15-研究完成判据与剩余缺口.md) 并由维护者签署后，才升级 Accepted。

> 注意：“研究四套”不意味着要复制任何一套产品的所有实现细节。我们只保留可验证并有必要的核心机制；像完整插件市场、分布式编排和任意热替换 Trusted Kernel 并不进入第一版。
