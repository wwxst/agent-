## 2. 逐项动态事实

### CODING-M0-01：遵守风险声明，编辑工具无法运行

在 `ToolRegistry` 注册 `risk: 'write'` 的 `repo.patch`，用 `FakeProvider` 模拟模型强行调用此工具。

**真实结果**：`ToolRegistry.modelSpecs()` 不向模型公开该工具；`preflight()` 记录 `denied / M0_DENIES_SIDE_EFFECTS`；修改函数调用次数为 0，源文件保持原样；下一轮 Provider 能看到拒绝结果。这是当前 M0 权限合同**正确拒绝写操作**，并不是实现缺陷。

### CODING-M0-02：在明确不安全的研究适配器下，完整编码循环可用

为隔离实验在 `mkdtemp` 工作目录创建了实际 `calc.mjs` 和 `calc.test.mjs`，注册三个测试用工具：`repo.read`、`repo.patch.unsafe-fixture`、`repo.test.unsafe-fixture`。

**重要条件**：实验中的 patch 工具为了绕过只读入场**故意错误声明为 `risk:'read'`**；测试执行器使用 `spawnSync(process.execPath,['--test',...])`，在临时目录生成真实 Node 子进程。这些适配器运行在 Kernel 进程权限下，**没有** OS 沙箱、生产审批或外部副作用收据。不要复制为正式工具实现。

六个模型步骤：

1. `repo.read` 读取 `add(a,b)=a-b` 的缺陷实现；
2. 模型调用 patch 写入仍错误的 `a*b`；
3. 真实 Node `--test` 进程执行测试，退出非 0；
4. 脚本式 Provider **检查上一步返回的失败内容**，再调用 patch 修成 `a+b`；
5. 再次运行真正的 Node `--test` 进程，退出 0；
6. Provider 检查成功内容后，输出完成回复，Turn 状态 `completed`。

**实际审计**：6 个 `model.started`，5 个 `tool.intent`、5 个 `tool.receipt`、5 个 `tool.result`，最后事件 `turn.completed`；两次真实测试结果为 `[failed, passed]`。因使用脚本式确定性 Provider，这一事实证明 Kernel 编排能够消费真实测试反馈，**不证明真实 LLM 自主选择或生成修复方案的质量**。

## 4. 与参考内核可见源码对照（静态，非新动态跑分）

- **Pi Coding Agent**：`read`、`edit`、`write`、`bash` 都是具体产品工具；`write/edit` 支持可替换文件操作，编辑具备匹配/重叠检查及文件变更排队；Bash 操作使用子进程并处理超时和进程树终止。参考 `earendil-works/pi@a92283056d915c758799fcd904948ff0cb42628c` 的对应 `packages/coding-agent/src/core/tools/` 文件。
- **Codex**：`codex-rs/core/src/tools/handlers/apply_patch.rs` 将 Patch 处理连接到 `ToolOrchestrator` 与实际执行环境、批准/沙箱路由，区别于仅在模型 JSON 中声明可写工具。参考 `openai/codex@68b67f0ff4f8d53d2c582e059b2c3b589f21ac93`。
- **Claude Code**：CLI 2.1.304 样本中的工具调用连接流式调度、权限处理和 `Tool.call`；此处只引用此前锁定的静态源码分析，**没有**再跑 Windows CLI，也不外推跨平台。

## 5. 最小下一阶段设计门槛（候选，不是已批准架构）

建议首先做一个**纵向能力切片**而非重写 Loop：

1. 独立 Workspace Host，固定 Repo/Workspace 根与操作身份；工具 `file.read`、受限 `file.patch` 和 `test.run` 分别具有明确风险与授权。
2. 写入前保留原文件内容版本或 Hash，保证目标路径范围、补丁前置条件、符号链接和 TOCTOU 校验；文件写入必须通过可信 Host，不能由模型提供进程内 JS。
3. 测试命令默认由可信的预定义命令模板执行，绑定工作目录、环境、超时、输出上限和子进程资源收敛；不能把任意 Shell 当成无风险只读操作。
4. 与 `tool.intent`、Host `STARTED`、`receipt`、`outcome_unknown` 的原有持久事实相容；审批/租约不能由插件提升。
5. 验收同时覆盖补丁成功、失败回滚/不可自动重试、测试失败再修复、取消、重复调用、Worker 杀死及恢复、越界文件访问拒绝。任何代码提交前先定义规范性测试，不沿用此次故意不安全的样例为生产标准。

**架构决策建议**：保留已经动态验证的最小 Agent Loop / 日志 / Host 安全基础作为候选；下一步优先验证如何增加最小的生产级写工具与测试执行器，而不是现在整体推翻内核。该建议不等于正式冻结架构。
