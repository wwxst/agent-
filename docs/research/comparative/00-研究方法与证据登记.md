## 何谓“研究透”，而不是写很多文档

一个子系统只有满足以下条件才能在**指定版本和平台**上标为“研究完成”：

1. 定位真实入口、核心函数、关键数据结构、调用的执行宿主；
2. 画出正常/异常/取消/重试/恢复路径，明确每条路径谁拥有状态；
3. 指出输入信任边界、权限执行边界、副作用不可逆边界；
4. 用确定性测试和必要的动态故障注入验证至少关键不变量；
5. 固定材料的版本与哈希或 Git SHA，提供可复核位置；
6. 标明不可见的服务端、OS 依赖与 Feature Gate，禁止以推测填补；
7. 在**同类任务和统一环境**下做对照实验，才讨论性能、可靠性或效率优劣。

上述标准很严格：**本轮主要满足 1、2 的一部分和 5；4 和 7 还没有完成。** 因此不会宣称四套已全部“研究透”。

## 事实等级

- **A1 本轮直接读取新版打包代码**：版本 2.1.304 / Desktop 3.1623.1，给出 JS 模块、字符偏移、SHA-256；能证实存在路径，不证明已在运行中走过。
- **A2 本轮直接读取固定提交公开源码**：给出仓库 SHA、文件与行号；能证实源代码逻辑，不替代动态测试。
- **B 旧版样本直接确认**：仅证明 CLI 2.1.88。
- **C 官方架构说明**：辅助解释意图，但必须与源码一致才推论行为。
- **T 运行确认**：具有可复现的命令、环境和结果；**本轮没有 T 级外部 Agent 执行验证**。
- **U 未确认**：缺少材料或尚未走完整个依赖链，严禁写为确定事实。

## 反向研究的安全纪律

- **不运行**用户 ZIP 里的 `claude.exe`、未知 Node 脚本或 DLL，只读解包扫描 JS；不触发网络、Shell、系统权限。
- 不将整个第三方源文件复制进 `agent-`；仓库保存结构化分析与必要的简短标识。
- 不将 JS 字符 offset 当成行号；在 README 或报告中可根据哈希复查。
- 不用静态源码猜许可证结论、商业可用性、官方发布真实性或模型能力排行。
- 区分安全策略“有代码”“启用条件满足”“OS 真正执行”“抗绕过测试通过”四个等级。

## 审计范围与负面证据

某个函数名不存在不能说明机制不存在；它可能被内联、别名化、移到其他模块。尤其 Claude 2.1.304 的 Bun 虚拟模块与打包符号不能与 2.1.88 TS 函数建立自动一一映射。

**不在本轮覆盖内**：Anthropic 云端模型推理、OpenAI 远程模型服务、DeepSeek 模型内部架构、第三方沙箱内核全部系统调用、跨版本全部历史以及真实压测。测试环境、沙箱能力、Agent 运行模式不同也不可直接比较“谁更强”。
