## 2. 两个新增规范性故障注入

### HOST-RACE-01：并发取消的 Unknown 传播

实验启动同一 Host 的两个 `read.sleep(1500)` 请求，等待 SQLite 中出现两条真实 `STARTED` 记录；中途 Abort 其中一个请求。

**实际观测（两种 Node 版本相同）**：Host 终止；两个请求的调用者均收到 `TOOL_OUTCOME_UNKNOWN`；账本留下两条 `started`；另起 Host 仍拒绝重放相同 ToolCall ID。这验证了当前 Host 对并发调用共享进程终止时的保守处理，而不是错误地给未确认的调用记 `failed` 或 `succeeded`。

**限制**：当前工具仅 sleep，无外部不可逆操作；`STARTED` 不能作为“副作用已发生”的证明，Unknown 也不说明进程树、网络服务或外部 API 已被补偿。

### HOST-RACE-02：两个独立 Worker 竞争同一 Intent

实验启动两个 `ProcessToolHost` 进程，使用同一个持久化 Tool Intent 和活跃 Lease；第一个 Worker 写入 `STARTED` 后，第二个 Worker 并发尝试执行相同 `callId`。

**实际观测**：第二个 Worker 得到 `TOOL_OUTCOME_UNKNOWN` 而不重复领取，第一 Worker 正常返回 `slept:1400`；账本只有一条 `succeeded` 行。此行为由 SQLite 的交易和唯一键共同保护。

**限制**：验证的是相同 Session/Turn/Call ID 的争用，不证明两个**不同** ToolCall ID 对同一外部幂等资源天然具有 exactly-once 语义。

## 3. 重查以前被低估的真实 Linux 沙箱实验

通过重新阅读 [Run 40629835558](https://github.com/wwxst/agent-/actions/runs/40629835558) 的原始 Job 日志，已确认以下用例显示 `ok` 且**没有 `# SKIP`**：

- `M3 sandbox: actual bwrap namespace worker uses durable Host ledger if supported`：真实 Bubblewrap Worker、内核命名空间 PID/身份校验，以及持久化收据。
- `M3 sandbox: real namespace denies parent-only file, code write and host loopback; permits dedicated SQLite dir`：受限进程实际尝试读取宿主独有文件、修改代码目录和连接宿主回环端口，分别被拒绝；专用 DB 目录可写。
- `M3 hardening: actual namespace enforces tmpfs size`：验证 private tmpfs 的实际容量约束，而不仅是参数字符串。
- `M3 seccomp: real strict namespace denies socket syscall with EPERM`：网络 syscall 实际被过滤。
- `M3 seccomp: real seccomp-filtered Worker can still persist Host ledger and receipt`：受过滤的 Worker 完成最小白名单工具及 SQLite 记录。
- `M3 seccomp: failing to provide filter fd cannot initialize a strict sandbox`：缺少强制 Seccomp FD 时拒绝启动。

这些属于**GitHub Actions Ubuntu Runner 的特定 Linux 运行条件下已执行的 S3 证据**；不应继续将其写为全部 NOT RUN，但这**不是**其他内核、内核版本、容器配置或多平台的 S4 认证。

## 4. 确认跳过 / 不可外推的范围

在对应运行中，明确标记 `# SKIP` 的测试为：`M3 enforced: existing bounded cgroup does not authorize an invalid sandbox or fallback`，原因是 CI 的父 cgroup 没有有限的 memory/pids/cpu v2 配额，不能满足该验收场景。其他有关 cgroup 的静态/模拟限制测试通过，**不能代替真实专用 cgroup 入场、运行和回收验证**。

`ProcessToolHost` 当前仅注册 `read.echo`/`read.sleep` 的只读白名单，默认的非 Sandbox Process Host 与 opt-in Enforced Linux Host 是不同的安全边界；不能把“在进程内 Scheduler 用受信任函数写文件”的 B01/B06 证据套在受限 Worker 上。

**仍未验证**：生产环境内核版本差异、真正 Shell 子孙进程的终止、断电/文件系统物理持久性、不可幂等外部 API 的执行/补偿、跨平台 Seccomp/namespace/cgroup 边界，以及 Codex/Pi/Claude 在同条件下的动态对比。

## 5. 结果应用与架构讨论

优先保留经实证的 Process Host `STARTED` 防重、故障 Unknown 和真实 Linux Fail-Closed 基础；避免为尚未开放的 Shell 或外部插件仓促设计庞大恢复框架。后续若开放有外部副作用的工具，必须先完成隔离、权限、收据及重放窗口的专门验收。

本次提交新增两项**符合期望的规范性测试**，可以作为持续回归；与第 19 号报告刻意重现现有问题的观察型探针性质不同。
