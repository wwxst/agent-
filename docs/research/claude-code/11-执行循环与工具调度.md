# 11 · Agent Loop、流式工具调度与结果回填

> 证据：A（2.1.304 JS）+ B（2.1.88 还原源码）；未进行运行时测试。新版定位格式为“模块文件@字符偏移”。

## 一、从交互到循环，不是一次模型请求

旧版 [QueryEngine.ts](https://github.com/wwxst/-/blob/main/restored-src/src/QueryEngine.ts#L675) 约 675 行调用 query 并异步消费事件；[query.ts](https://github.com/wwxst/-/blob/main/restored-src/src/query.ts#L219-L307) 的 query 交给 queryLoop，后者初始化跨迭代 State 后进入 while(true)。旧版 State 至少持有 messages、toolUseContext、autoCompactTracking、turnCount、恢复计数和 transition。它区分一次用户任务与其中的多次模型请求。

新版 chunk-smbjjyps.js 的 YL（@135116）包装 su（@137532），su 中 iu（@141376）处理一轮，末尾把 messages、上下文与 guards 组成新状态；在 @209036 产生 next_turn/next_round 类型的迁移，在 @209492 的循环继续迭代。chunk-3s96qz8g.js@63588 的上层 Driver 从输入/Turn 队列消费，输出事件并处理终态。**这是两个层次**：外层用户 Turn 调度，不等于内层“模型→工具→模型”的迭代。

## 二、模型请求的数据边界

新版 chunk-smbjjyps.js@162542：通过 I.callModel 传入 messages、systemPrompt、thinkingConfig、tools、abort signal 和 options。其下游 chunk-4b60tdnk.js 中有 zIt（@2690290）、mgn（@2705215）、Xmn（@2705953），并在 @2743622 生成模型请求对象；@2780615 实际调用 beta.messages.create，启用流式返回。旧版对应 query.ts 的模型调用与 services/api/claude.ts 中的 queryModelWithStreaming（约 752 行）。

可以确认：**执行控制在本地 Agent Loop，下一步建议与 tool_use 内容来自模型响应，真实工具执行仍由 CLI 工具栈承担**。这不揭示云端 Claude 模型怎样进行内部推理。

## 三、StreamingToolExecutor 的真实调度决策

旧版 [StreamingToolExecutor.ts](https://github.com/wwxst/-/blob/main/restored-src/src/services/tools/StreamingToolExecutor.ts#L76-L150)：

1. addTool 先按名称定位 ToolDefinition；找不到的工具生成关联 tool_use_id 的错误 ToolResult，而不是执行。
2. 使用 inputSchema.safeParse 校验参数；参数非法或计算异常时，并发安全判定回退为 false。
3. 通过工具提供的 isConcurrencySafe(parsedInput) 判断并发性。
4. 工具进入 queued 后触发 processQueue；若没有正在执行的工具，可以启动；若已有执行工具，则要求新工具与所有执行中工具均标记可并发。
5. 遇到不安全、需要独占的排队项时，不继续越过它破坏顺序约束。

新版 chunk-smbjjyps.js@53700-55450 保留了这些关键模式：注册工具、safeParse、isConcurrencySafe、processQueue、canExecuteTool。@181931 在助手消息中出现 tool_use 后 addTool，不必等所有工具调用都结束才开始调度。@61000-61900 的 getCompletedResults/getRemainingResults 处理中途结果与进度。

**重要边界**：“streaming”指收到一个可调度的完整 tool_use block 后可以开始执行，不等于可使用尚未解析完的 JSON 字符片段执行工具。也不意味着所有工具都并行或所有修改不同文件的调用互不冲突。

## 四、实际执行与回填

新版 chunk-smbjjyps.js@59131 把一个排队 ToolCall 交给 wG。chunk-4b60tdnk.js 中：

- wG（@3957580）处理工具名、别名、路由和缺失工具；
- AYr（@3967595）处理具体输入/前置执行链；
- Svr（@3976664）处理权限决定和可能的输入更新；
- 未获允许时 @3980050 形成 is_error 的 tool_result；
- 允许时 @3985545 进入 tool.call；
- @3987768 调用 mapToolResultToToolResultBlockParam；
- @3993507 包装结果消息。

旧版 query.ts@842 addTool 后，@851-859 从 getCompletedResults 读取已完成的工具结果；@1012-1029 在 abort 时处理剩余结果；@1715-1719 将此前的 messages、assistantMessages 和 toolResults 构成下一轮 State。新版 chunk-smbjjyps.js@199861 排空 getRemainingResults，@209036 把 assistant 与 ToolResult 添加进下一轮消息。

**重要不变量**：每次 tool_use 必须能找到对应 tool_result，包括未知工具、拒绝、取消、流失败时的合成错误；否则模型上下文可能产生孤立工具调用。旧版确实存在为此补齐合成 tool_result 的代码，不应误认为它保证外部副作用已被取消。

## 五、取消、并发和失败语义

旧版 StreamingToolExecutor.ts@153-231 可为 sibling_error、user_interrupted、streaming_fallback 生成合成错误；中断原因包含当前工具声明的 interruptBehavior（cancel / block）。@408-470 将已完成结果、进度消息按明确顺序交给外层。新版 chunk-smbjjyps.js@55700 出现 user_interrupted、conversation_ended、streaming_fallback 等分支；@61800 的结果迭代等待工具 promise 或新的进度。

旧版 query.ts@1704-1711 在达到 maxTurns 时明确返回 max_turns；新版 chunk-smbjjyps.js@197495、@208776 也包含最大轮数与 stop-hook 相关限制分支。**不能据此声称任何版本在所有配置下都有全局硬预算**；不同限制有不同作用域和配置。

## 六、值得自研 Kernel 吸收的机制

- 把 User Turn 调度器和 Model Step Loop 明确分开。
- 每个 ToolCall 有稳定 ID、完整参数、工具版本、输入指纹和终态。
- 调度前必须完成 Schema 校验；读工具可以有并发策略，修改型工具另做资源冲突检查。
- 并发安全不应只凭插件返回布尔值：建议工具声明读写文件/资源集合，调度器做冲突图或保守独占判断。
- 流中止后要补齐模型可见的工具结果，但同时保留宿主副作用状态为 unknown（如未确认）。
- 事件先提交再对外宣称工具完成；进度片段和持久事实分不同通道。
- 禁止未经权限检查、未经写入持久执行意图就直接调用 Tool Host。
