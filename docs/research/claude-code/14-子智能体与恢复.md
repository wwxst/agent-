# 14 · Subagent、Fork、Transcript 与恢复边界

> 证据：旧版 2.1.88 提取源码直接确认多条完整分支；新版 2.1.304 可确认对应子 Agent 入口。未运行真实后台任务、进程崩溃或断点恢复。

## 一、Subagent 不是修改 System Prompt 的同义词

旧版 [runAgent.ts](https://github.com/wwxst/-/blob/main/restored-src/src/tools/AgentTool/runAgent.ts#L248-L329) 入口显式接收：agentDefinition、promptMessages、toolUseContext、canUseTool、isAsync、maxTurns、availableTools、allowedTools、工作树路径、持久化相关状态等。这意味着 Subagent 是一次可独立配置的 Agent 执行。

runAgent.ts L697-714 调用 createSubagentContext：传递 agentId、agentType、初始消息、readFileState、AbortController、getAppState 等。同步与异步 Agent 的状态共享策略不同：同步分支共享部分回调，异步 Agent 使用其自己的上下文和 AbortController。

新版 chunk-k3djx6vq.js@87525 有 async generator ZR 子 Agent 主入口，@100692 构建子 Agent query 配置；@107819 实际调用 nt.options.runQuery，传递 messages、systemPrompt、canUseTool、toolUseContext、maxTurns 等。**两版本共同说明子 Agent 重用执行循环，但参数和上下文经另一层准备**；不能据此推断新版所有子 Agent 的确切隔离级别。

## 二、权限继承有复杂例外，不能想当然

旧版 runAgent.ts L412-478 对 permissionMode 的处理不是简单取父子权限交集：

- 当父上下文处于 bypassPermissions 或 acceptEdits 等模式时，子 Agent 定义的模式不一定覆盖；
- 异步 Agent 默认可能设置 shouldAvoidPermissionPrompts，避免无交互时卡住；明确允许交互或 bubble 模式有另一条路径；
- allowedTools 存在时，会替换从父 Session 派生的 allow 规则，但保留 SDK cliArg 明确授权来源。

新版 chunk-k3djx6vq.js@91300 同样可见 shouldAvoidPermissionPrompts、awaitAutomatedChecksBeforeDialog，以及 cliArg/session 层规则处理。

**自研决策**：Child Capability 默认是 Parent 授权能力的子集，Agent 工具清单不等于授权令牌；任何来自 CLI 参数的高权限也必须经策略层显式限定作用域。这不是在宣称 Claude 本身实现了严格子集。

## 三、子 Agent 的事件转发与消息记录

旧版 runAgent.ts L721-742：

- 可以向上层报告与提示词缓存兼容的参数；
- 启动时调用 recordSidechainTranscript(initialMessages, agentId)；
- 独立记录 agentType、worktreePath、description 等元数据；
- 其中初始 Transcript 与 Metadata 写入采用 fire-and-forget 并 catch 记录错误，注释明确不阻塞 Agent。

旧版 runAgent.ts L747-805：

- 子 Agent 通过同一个 query(...) 执行内层 Loop；
- 将模型流式 message_start 指标转发给父任务；
- 对普通消息调用 recordSidechainTranscript，按 UUID 建立父消息关系；
- 错误记录以 catch 写日志处理，不是将持久化失败直接视为任务失败；
- 使用 maxTurns 或 AgentDefinition.maxTurns 限制运行轮数。

L816-820 在 finally 中清理子 Agent 专属 MCP 服务器与 session hooks。

**关键架构判断**：这是一套兼顾产品交互与效率的子任务机制，但仅凭此处代码**不能证明**每个副作用都具有 crash-safe 的先写日志后执行语义。尤其初始日志写入与元信息都是非阻塞写入。这是我们自研内核需要更严格设计的恢复边界。

## 四、Fork 模式不是普通子 Agent

旧版 [forkSubagent.ts](https://github.com/wwxst/-/blob/main/restored-src/src/tools/AgentTool/forkSubagent.ts#L19-L71) 有 feature gate：省略 subagent_type 时可把父 Agent 的完整对话上下文和已渲染系统提示传给子 Agent，后台启动，使用 bubble 模式将审批转交到父端。为了保持 Prompt Cache 前缀一致，Fork 还使用父工具集及原样系统提示词。

同文件 L73 起有递归 Fork 保护；L111-163 会为父助手同一条消息中的 tool_use 生成配对占位 tool_result，再构建给子 Agent 的 fork 消息，以免创建孤立工具调用。

**仅能确认旧版有上述受 Feature Gate 控制的设计**。不能宣称所有 2.1.88 安装都启用了 Fork，也不能推定 2.1.304 默认相同。对我们的内核，复制父对话属于显式 Fork 策略，而不是所有 Task 默认方式。

## 五、后台恢复会先修复历史一致性

旧版 [resumeAgent.ts](https://github.com/wwxst/-/blob/main/restored-src/src/tools/AgentTool/resumeAgent.ts#L42-L105)：

1. 根据 agentId 读取子 Agent Transcript 与 Metadata；
2. 无 Transcript 就明确失败；
3. 清理 unresolved tool uses、孤立 thinking-only 消息、纯空白 Assistant 消息；
4. 重建用于压缩或替换大工具结果的 replacement state；
5. 检查原工作树路径是否仍存在；若不存在，源实现回退到父 cwd；
6. 使用记录的 agentType 区分普通 Agent 与 Fork。

resumeAgent.ts L178-205 的构建过程避免再次附上 Fork 的父上下文切片，因为它已经包含在 Transcript 中，再添加可能导致重复 tool_use ID；随后以旧 Agent ID 重新注册异步任务。

**我们的内核不应静默模仿“工作树丢失则回退父 cwd”**：如果任务将修改代码，执行路径变化可能造成误操作。建议恢复时报告 WorkspaceMissing，并由用户确认新执行位置；只读任务可采用受控降级。

## 六、持久化策略：普通历史写盘与可靠作业日志不同

旧版 [sessionStorage.ts](https://github.com/wwxst/-/blob/main/restored-src/src/utils/sessionStorage.ts#L532-L568) 的 Project 使用 pendingEntries、per-file 写入队列、flushTimer、activeDrain 与 pendingWriteCount。L841-861 的 flush 会等待活动 drain 与待写操作，L2572-2583 的 appendEntryToFile 使用按行追加 JSON 和文件权限设置。对于用户恢复历史、展示消息，这些机制有明确用途。

但**追加 Transcript 不等于具备分布式事务语义的 Event Journal**。静态源码目前不足以证明：ToolCall 意图提交和文件/Shell 实际副作用形成了严格原子性，也不足以证明外部命令失败时拥有 exactly-once 效果。因此不将 Claude CLI 当前会话文件直接作为我们自己的工具幂等协议模板。

## 七、自己的 Task / Subagent Engine 必须强制的语义

- 每个 Child 拥有 taskId、parentTaskId、独立预算、Context、ToolScope、权限子集和 CancelToken。
- Parent 对 Child 的批准要绑定明确 ToolCall，不借用泛化的“父端已批准一切”。
- 子任务提交、工具执行意图、审批及结果存入同一可信事件体系，支持进程恢复。
- 允许同步/异步工作，但 Child 结束必须释放资源（MCP、Hooks、文件句柄、订阅、沙箱）。
- Fork 复用父上下文时确保 tool_use/tool_result 成对，并且 Token 预算重新计算。
- 后台任务保留独立工件清单、进度事件与失败原因，不用自然语言“做完了”代替状态。
- 丢失原宿主工作区、审批失效或执行结果不确定时暂停并要求重新确认，不自动换位置或重试非幂等操作。

## 八、拟议故障测试

T14-01 Parent 取消→按规定级联 Child Cancel，记录尚未结束的外部操作。  
T14-02 Child 初始化失败→释放已创建资源与能力，事件完整。  
T14-03 后台权限需要用户确认→暂停或拒绝，不静默自动放行。  
T14-04 初始 Transcript 落盘失败→不产生无法恢复且已执行副作用的“幽灵任务”。  
T14-05 原工作树被删→停止写入，不在父 cwd 偷偷继续。  
T14-06 Fork 恢复不会重复插入已有 tool_use，重放游标与版本一致。  
T14-07 Child 有最大深度/并发/工具次数/Token/时间预算，不能依靠 Prompt 自我约束。  
T14-08 安全作用域在正常、异常、取消以及崩溃恢复后都完成资源清理。
