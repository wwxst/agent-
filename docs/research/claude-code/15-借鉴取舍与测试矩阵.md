# 15 · 从 Claude Code 源码研究到自研 Agent Kernel 的设计决策

> 文档性质：研究结论和工程建议；不是直接移植 Claude Code 的源码，也不是已经完成的实现。

## 一、综合判断

Claude Code 发布产物中可找到真正的 Agent Loop、增量工具调度、权限决策、工具回填、上下文压缩及子 Agent 生命周期，不只是 GUI 包装层。旧版 Source Map 提取代码给出了可读函数与大量异常路径；新版 2.1.304 JS 进一步确认对应的主调用链仍存在。但不同版本、平台与 feature gate 的完整行为仍需实际测试。

**最值得学习的是它在执行链中的细节，而不是直接复刻它的模块数量。**

| 子系统 | 源码直接确认的机制 | 自研应该吸收 | 自研应改进或另行设计 |
| --- | --- | --- | --- |
| Agent Loop | Generator / 状态对象 / next round 迭代 | 明确 Stop、Abort、Continue、MaxTurns | 持久化 Turn FSM，不仅依赖运行中 generator |
| Model | 请求前组装上下文、流式响应、tool_use | Provider Adapter 统一工具流 | 多厂商兼容测试，不做 Anthropic-only 内核 |
| Tool Scheduler | safeParse、isConcurrencySafe、排队及进度 | 读操作并发，写操作受冲突规则限制 | 不信任插件自评并发；加资源锁/乐观版本 |
| Tool Result | 每个 ToolCall 配对结果，拒绝/取消可合成错误 | 规范化结果并回填 | 区分模型可见 Result 与操作系统副作用状态 |
| Permission | deny、ask、allow、Hook、工具权限 | 分阶段决策、最新状态、参数重核对 | 权限根与 OS 沙箱不可由插件覆盖 |
| Context | 触发阈值、自动/局部压缩、PreCompact、失败熔断 | 独立预算和压缩状态机 | 持久检查点、工作事实不由摘要覆盖 |
| Subagent | 子上下文、maxTurns、后台、Fork/Resume | 任务树、子 Agent 重用 Loop | 能力严格减权、恢复前宿主身份/工作区校验 |
| Session | JSONL 历史记录、异步写队列、Flush | 可追溯历史 | 事务型意图日志、未知副作用禁止盲目重试 |

## 二、不能模仿的几个潜在风险

### 风险 R1：流式 ToolCall 调用太早

从已有完整 tool_use block 入队是有效的优化，但不应让部分 JSON 或未验证的 Provider 片段直接进入 Tool Host。我们使用 proposed → validated → authorized → prepared → started → result 的严格序列，且向模型返回结果和外部副作用结果分离。

### 风险 R2：Hooks 和“允许执行”混淆

PreToolUse 是策略输入，不能赋予当前 Session 不具备的 OS 能力。若修改后的参数发生变化，原审批全部失效；Tool Host 重新验证路径和实际运行环境。

### 风险 R3：上下文压缩丢掉真实任务事实

摘要仅仅是模型理解用的派生内容，不能作为批准工具、确认外部 API 成功或恢复任务的最终事实来源。所有 Checkpoint 应包含被摘要消息范围、摘要版本、未完成调用清单和成本记录。

### 风险 R4：异步子 Agent 的“写了日志再说”

原版某些日志写入明确允许失败并继续工作，这是交互体验与完整性之间的工程取舍。我们应把不可恢复的写入失败当作不能安全继续产生高风险副作用的状态；绝不声称第三方做到了跨进程 exactly-once。

### 风险 R5：把跨版本静态代码当做性能基准

2.1.88 与 2.1.304 能确认共同的概念机制，但没有一致的任务集合、模型配置、延迟/成本数据或端到端沙箱测试。不能给出哪个版本绝对优于另一个，也不能将旧版阈值直接写成新版不变量。

## 三、建议固定的自研核心状态机

用户级：

- Session → TurnQueued → TurnRunning → TurnCompleted / TurnFailed / TurnCancelled / TurnInterrupted。
- 同一 Session 的多个 Turn 有明确排队、Steering 或拒绝语义。

模型 Step：

- ContextPrepared → ModelStreaming → ModelCompleted / ModelFailed / ModelCancelled。
- 工具参数未完全结束前只能显示进度，不能执行。

工具级：

- Proposed → Validated → PolicyChecked → ApprovalPending（可选）→ IntentDurable → Running → Succeeded / Failed / OutcomeUnknown。
- 重试与恢复依据工具幂等等级、宿主收据、参数指纹决定，不能靠模型“再试一次”触发第二次外部提交。

上下文：

- Estimate → BudgetCheck → OptionalCompaction → CheckpointCommit → NextModelRequest。
- 摘要失败与中断必须有独立状态，且不会修改历史事件。

子 Agent：

- ChildScheduled → ScopedResourcesPrepared → ChildRunning → ChildTerminal → ResourcesReleased。
- Parent/Child 的预算与权限在创建时锁定；运行中修改规则只可进一步收紧或触发重审批。

## 四、架构与参考项目之间的关系

- **Pi**：保持 Loop 最小可读，避免无限膨胀的巨型调度文件。
- **Codex**：强化 Turn、权限、事件、沙箱、恢复以及客户端协议。
- **Claude Code（本次源码研究）**：吸收流式 Tool Scheduler、复杂权限叠加、压缩失败处理、子 Agent 资源管理。
- **DeepSeek Harness**：吸收 Registry、Scope、可逆资源生命周期和 Profile。
- **我们自己**：坚持状态机与授权根不可由业务插件跳过，建立强制事务/幂等边界。

## 五、实施建议（对应仓库现有 M0-M4）

**M0**：AgentEvent/ToolCall/Turn Schema、可测 FakeProvider / FakeToolHost、静态 Registry、Policy Decision 类型、MemoryEventStore。

**M1**：只读工具的流式并发 + 不安全工具独占，工具 ID 成对回填，取消与最大步数限制。应先使用 Fake 模型测试队列交错执行。

**M2**：持久 Event Journal、权限审批、独立 Tool Host、故障注入、上下文压缩检查点、未知外部副作用恢复机制。没有真实沙箱则不启用危险 Bash。

**M3**：Skills、MCP、Hooks、Subagent、每 Agent 作用域和任务预算继承。同步/异步都不能越过权限根。

**M4**：远程执行、浏览器、媒体工作流和可观测仪表盘。多 Host 时明确身份、重新认证和宿主副作用确认。

## 六、可量化验收门槛（建议）

| 领域 | 需要的验收 |
| --- | --- |
| 状态正确 | 状态机属性测试；非法终态回退 0 次成功 |
| 工具调度 | 交错、乱序完成、并发冲突、重复 ID、超时与取消均有测试 |
| 权限 | deny 覆盖 allow、审批绑定参数/宿主、Hook 改参触发重审批 |
| 持久化 | 杀进程故障注入；恢复后未知工具不自动重试 |
| 上下文 | 预算硬上限、摘要失败、重复压缩、长历史保留任务事实 |
| 子 Agent | 深度/并发/步数上限、父子取消、权限不扩大、资源回收 |
| 客户端 | 事件重放、重复提交请求幂等、审批重放拒绝 |
| 外部产物 | 路径/文件版本可验证、无静默换宿主/换工作目录 |

“0 次成功”表示自研测试的验收标准；目前无运行结果，不能冒充已达成。

## 七、第二轮未覆盖部分和后续调查

仍需做静态或动态深入调查：

1. 新版 2.1.304 代码中，完整的 Tool Host / Sandbox 平台分派和真正的 OS 权限限制。
2. 2.1.304 的压缩阈值、触发优先级、多个压缩方案的 feature gate 组合矩阵。
3. 不同 Subagent 类型的后台协作、恢复、取消与工具授权的整体状态机。
4. Desktop UI / SDK / CLI 的真实控制协议中的权限、取消、恢复以及跨进程丢消息情形。
5. 构建一个“同模型、同任务、同工具协议”的 Harness 对照测试，验证不同策略的实际收益和代价。

要解决这些问题，必须逐项执行专门的工具/测试，而不是把未知部分写成确定事实。

## 八、结论

自研内核应借鉴 Claude Code 已确认的**具体机制**，而不是依赖 Claude Code 的 CLI 作自己核心。执行层可流式和并发，**但安全层、事实层与恢复层必须比一个纯交互式 Agent Loop 更严格**。这是本项目的设计目标，而非 Claude Code 已经实现了这些增强的断言。
