> 研究日期：2026-10-24；状态：第二轮静态分析；不代表运行测试通过。  
> 研究范围：用户上传的 Claude Code CLI 2.1.304 / Claude Desktop 3.1623.1 样本，以及用户公开仓库 wwxst/- 中的 Claude Code 2.1.88 Source Map 还原文件。

## 为什么单独建立研究目录

之前的 [第一轮总览](../../10-Claude-Code-内核源码追踪.md) 主要确定了模型—工具—下一轮模型的调用路径。本目录按子系统展开，明确不同版本的证据边界、异常路径与自研 Kernel 的架构结论，不把静态代码解释成实际运行验证。

## 证据如何定位

**2.1.88 还原源码**：代码已提交到用户旧仓库 [wwxst/-](https://github.com/wwxst/-)，路径以 restored-src/src/ 开始。行号以该仓库 main 在 2026-10-24 可见版本为准；建议后续引用时固定提交 SHA。该仓库 package/package.json 直接声明 CLI 版本 2.1.88，其 extract-sources.js 明确从 package/cli.js.map 的 sourcesContent 提取代码。虽然保留了可读的 TypeScript 文件名和注释，但不代表得到原始版本控制历史或可完全构建的私有仓库。

**2.1.304 发布产物**：从项目 ZIP 中直接读取 cli-2.1.304/modules/*.js 的解压后字节，再将 UTF-8 内容中 0 基字符偏移作为定位。符号被缩写（如 su、iu、vs、wG），不能猜测原始 TS 符号。对下面四个模块做了 SHA-256 校验：

| chunk-k3djx6vq.js | 1b4dc9236bf90b77cd9d9d13aa82f67c6a792920e9253d92ef402a2f6dd615fe |

附加新模块 chunk-3s96qz8g.js 的 SHA-256 为 6728e5e954398456230c593523d4d391cee0decbeb3c2b9fe7b28e63ffb4fe5f。

复核方式：用 Python 的 zipfile.ZipFile 按模块名查找并读出成员，decode('utf-8') 后按给定 offset 截取上下文。哈希只证明本次分析文件的同一性，不构成官方发行来源、数字签名或供应链真实性的独立鉴定。

## 证据等级

| 标签 | 定义 |
| --- | --- |
| A：新版直接确认 | 2.1.304 实际 JS 中存在具体调用或条件；只断言该代码分支存在 |
| B：旧版直接确认 | 2.1.88 还原源码直接有函数和逻辑 |
| C：跨版本确认 | A 与 B 能定位相同的概念机制，但不是“逐行同源”证明 |
| D：接口/报告 | 只见 SDK 接口、文档或随包报告；不作为核心行为的独立证明 |
| 未验证 | 未运行真实 CLI/模型/权限/OS 沙箱，不宣称端到端行为 |

注意：运行时 Feature Gate、平台选择、设置、主线程/子 Agent 路径可能改变实际执行流程。尚未验证这些版本的实际工具成功率、隐私、安全级别或完整恢复正确性。

## 研究纪律

- 只记录精确函数、条件与调用关系，未知的部分标“未验证”。
- 不把模型内部推理、云端授权服务或 Desktop 后端，混写成 Claude Code CLI 本地源码。
- 不把旧版例外路径硬套到新版；每次转移结论都说明证据。
- 不将第三方的源代码原文复制到自研仓库，仅提交分析、接口草案、测试思路及必要的短标识。
- 研究结论不替代自研安全验证；尤其不得把 permission=allow 当作 OS 沙箱已经强制实施的证据。

## 当前不足

尚未启动或动态调试 CLI；没有对每个 feature gate 与 Windows/macOS/Linux 沙箱分支构建行为矩阵；未验证官方签名与实际发行下载流程；没有运行中故障注入；没有复核所有 Desktop 3.1623.1 的 UI→SDK→CLI 控制分支。以下文件讨论的是可以被静态源码支撑的设计事实。
