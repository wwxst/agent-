## 1. 设计目标、非目标与保证等级

### 目标
1. 一个 Conversation 可以跨 CLI/Desktop/API/UI 重开；Run、Task、HostProcess、ToolOperation 的生命周期不随客户端断线直接消亡。
2. 高吞吐 token streaming、并行工具、steer/followUp、subagent、MCP/OAuth/elicitation、local/remote tool hosts、checkpoint compaction、fork/reset。
3. 用户可查询 Run/Task/ToolOperation 的 accepted/running/completed/interrupted/unknown 状态与结果凭证。
4. 在执行外部副作用前持久化 Intent，Host 端重新校验授权与执行所有权；崩溃之后 fail-closed 或对账，不静默重放 unsafe 操作。
5. 对话历史、运行时任务、权限授权和 UI 事件各自有明确 source of truth。
6. 可选本地/远端 Host、隔离执行容器、OS sandbox 与多租户部署；接口小、可替换。

### 非目标/诚实保证
- 不保证不支持 idempotency / outcome query 的任意外部系统 exactly-once。
- 不保证 Provider 不重复计费，除非 Provider 支持 request ID/可查结果。
- 不保证 MCP server 收到 cancel 就停止其副作用。
- 不将日志写成功、进程退出、用户按 Stop、UI 看到响应视为同一成功事件。
- v0.1 不要求复制 Chord 的全量热更新、SSH 进程接管或 Claude 的所有专有功能；先把基本恢复合同做对。

### 可靠性等级
- R0：内存瞬时运行；不可声明崩溃恢复。
- R1：进程崩溃后重建已 commit 的 Session/Task/Receipt，并辨识 unknown operation。
- R2：明确配置的存储和 fsync/transaction 策略满足主机掉电模型；需真实断电/虚拟磁盘故障验证。
- R3：跨进程/跨主机 execution ownership fencing；依赖协调/存储条件写和 Host side token。
- R4：只对明确支持幂等键、幂等执行或已确认 outcome query 的工具提供可证的 effect-at-most-once/对账；其余保持 OUTCOME_UNKNOWN。

产品必须按部署和工具能力声明其达到的等级，不能笼统标记 Durable。

## 2. 逻辑模块与责任边界

| 模块 | 权威职责 | 明确不承担 |
|---|---|---|
| Agent Loop / Turn Planner | LLM stream、ToolCall 解析与校验、steer/followUp placement、finishTurn、retry decision | DB durability、Host 直接操作、权限例外 |
| Run Coordinator | 一个 Conversation 的执行代际、Turn admission/settlement、model request ID、并行工具批次、父子 Task | 执行 tool code |
| Durable Task Engine | Task 定义与 version、phase checkpoint、owner/wait DAG、scheduling/claim/abort/restart、checkpoint migration | Model-specific prompt 或 UI |
| Operation Journal | Tool/Provider Intent、operationId、policy/owner epoch、dispatch state、Receipt/Unknown、严格 commitSeq | 任意外部系统的原子 commit |
| Host Gateway | Tool routing、capability registry、host identity、transport、handshake、RPC queryOutcome/cancel/late response | 安全策略的最终决定 |
| Permission Authority | 资源身份、授权策略、审批票据、policy epoch、revoke、audit/fail-closed | 模型是否认为工具“有用” |
| Tool Runtime / Sandbox | 进程/容器执行、OS capabilities、实际 pre-execute permission+fence check、幂等或 queryOutcome | 上层 Transcript |
| Conversation Store | Immutable Entry、Edit/Redaction revision、branch/head/compaction marker、canonical transcript | Tool effect ledger |
| Context Projector | Canonical transcript → provider messages，toolResult matching，token budget、summary revision validity | 覆盖原始记录 |
| Model Gateway | Provider credential、model routing、stream state、deadline/retry、usage evidence、request ID | 自作主张重试 unknown request |
| Session/API & Event Hub | 用户命令 Submission、idempotency key、client auth、snapshot/commitSeq/cursor、UI subscriptions | 决定工具已完成 |
| Process Supervisor | Worker/Host process lifecycle、grace/kill、OS lock、ephemeral liveness | Task owner/operation receipt 的终局定义 |
| Registry & Extensions | 定义 tools/tasks/models/sections/MCP、schema/version、作用域；可信代码的注册 | 绕开 permission/sandbox gate |

推荐部署边界：
- 控制面：Run Coordinator + Task Engine + Journal/Conversation Store + Permission Authority，持有权威存储；
- 数据面：可独立启动的 Local/Remote Host + sandbox，执行真实 Tool；模型请求走 Model Gateway；
- 表现层：CLI/TUI/Desktop/Web/RPC，只通过 API/事件流交互，无权限跳过 Gateway 直接改 Journal；
- 插件/扩展：需要明确 trusted in-process 与 untrusted isolated 两档，不能假装所有扩展都安全。

## 3. 数据模型与写入合同

命名建议：
- ConversationId：对话标识；BranchId/EntryId + ContextRevision：不可变历史与可见模型投影。
- SubmissionId + clientRequestId：用户请求受理、排队、撤销、完成的幂等凭证。
- RunId / TurnId / ModelRequestId：Agent 执行与 provider request 身份。
- TaskId / TaskVersion / OwnerTaskId / OwnerConversationId：父子任务与 phase checkpoint。
- ToolOperationId：跨 Retry、Host Reconnect 保持稳定的外部效果身份；ExecutionAttemptId 标识具体投递。
- HostId / HostInstanceId / WorkerEpoch / LeaseToken：执行者身份及 fencing。
- PermissionDecisionId / PolicyRevision / ApprovalScope：具体操作的授权快照/变更条件。
- CommitSeq：单一权威数据库事务提交编号；EventSeq 是从 CommitSeq 派生的 delivery cursor。

控制面 DB transaction 需原子写入：Submission admission、Task checkpoint/ownership、Tool Intent/Receipt、Entry/Context revision、UI outbox、关联 usage/audit reference。不要跨事务先发可执行 Tool RPC 再补写 Intent。

ToolOperation 建议状态：

PROPOSED → AUTH_PENDING → AUTHORIZED → INTENT_COMMITTED → DISPATCHING → {RUNNING, NOT_STARTED, COMPLETED, REJECTED, OUTCOME_UNKNOWN} → {RECEIPT_COMMITTED, MANUAL_RECONCILIATION}

- AUTHORIZED 必须绑定 tool schema version、canonical args hash、principal、policy revision、scope、TTL、Host capability。
- NOT_STARTED 仅来自可验证“Host 未开始”的事实，不能由超时/连接关闭猜测。
- COMPLETED 只有带 Host operation ID + result hash/receipt 的可信执行端响应。
- OUTCOME_UNKNOWN 必须作为独立可查询状态，禁止自动当失败重跑 unsafe tool。
- 终态 Receipt 要与相应 ToolResult Entry、Task transition 同一 DB transaction。
- 取消和撤销是与 operation status 并列的 Intent，不得把 RUNNING 简单改为 CANCELLED 后遗失真实 effect。

DB 模型应支持唯一约束：Submission(conversationId,clientRequestId)、ToolOperation(toolOperationId)、Receipt(toolOperationId)、Task claim/epoch CAS、Stream cursor/commitSeq。跨多 worker claim 使用 storage transaction 条件更新，fencing token 由 Host 在执行前比对；单进程 Promise mutex 不能替代。

## 4. 三条关键交互时序

### 4.1 用户提交、模型流与并行工具
1. API 验证身份、requestId 去重，事务提交 Submission(accepted)+Run/Task admission，返回 SubmissionId（不是任务成功）。
2. Run Coordinator claim Task(owner epoch)；Context Projector 读取一致的 revision，Model Gateway 发模型请求/stream，保留 token stream 为临时 UI 事件，不声称 durable。
3. 模型返回 ToolCalls，解析/修复/schema 预校验，按 source order 创建候选 operations；Permission Authority 分别判断 allow/ask/deny，ask 阻塞在可恢复审批 Task。
4. 每个获准 operation 在执行前提交 Tool Intent、ToolTask phase、outbox dispatch；原子 commit 成功后 Host Gateway 才能发送。
5. Host 验证 lease token、policy revision、approval scope、args hash 和 idempotency key，再执行；如果这些条件失效则 reject/not-started。
6. 并行执行的完成时间保留在 Event stream；回填 LLM 的 ToolResults 严格按原始 ToolCall order。一个 operation unknown 时，当前 batch 必须阻止不安全的补发/下游 side effects。
7. Receipt + ToolResult + Task settlement 一次 commit；准备下一模型 Turn。任务 terminal 与 Submission completed 后再提供权威结果。

### 4.2 断网/Host crash/reconnect
1. Gateway transport disconnect 只标记 DELIVERY_UNCERTAIN，不能改为 NOT_STARTED。
2. 先查询 operationId 的 Host ledger/queryOutcome；若 Host 不支持，区分未发出的 outbox、已发但无 ack、已 ack/running。
3. 已知完成则提交迟到 Receipt correction；可证 never-started 才允许新 attempt；支持 idempotent key 的可按策略重试；其余 OUTCOME_UNKNOWN + human/API reconcile。
4. Worker/Host restart 先重新认证，再 CAS claim owner epoch、复核权限与 tool schema version，最后恢复 task phase。原 worker epoch stale result/late callback 只能做关联审计，不得修改新 owner 状态。
5. 网络断开不自动 revoke 已批准请求；policy revoke 则记录新的 epoch 并向 Host 下发 cancel/fence，重连时复核。

### 4.3 上下文压缩与历史脱敏
1. 基于 ContextRevision R、head、tail 和安全策略版本 P 选 candidate cut；摘要可在后台生成。
2. 摘要 ModelRequest 记录输入 hash/R/P、输出与费用状态，运行过程中可重试，但不得宣传 exactly-once 计费。
3. summary commit 之前在同一事务检查当前有效 ContextRevision、所有影响该输入的 redaction/edit epoch、权限标签与 cut candidate。
4. 变更涉及 summary 输入且无安全可证明的增量修正时，拒绝旧摘要并重新生成；必须允许保留 raw history 的访问控制、脱敏和物理删除策略分离。
5. 新 Summary Entry + ContextHead change + outbox event 同一 commit；Event Hub 按 CommitSeq 派发。ToolCall/ToolResult 不可在 provider context 中被切成非法配对。

## 5. 技术选择候选与取舍

- 主运行时：TypeScript/Node 22+ 是研究样本与现有生态的自然候选，但不是最终约束；需要比较 Go/Rust Supervisor 或隔离 Host 的审计/性能成本。
- 控制面 R1：单机 SQLite WAL + 严格 transaction/outbox/唯一约束，明确同步级别；R2 需同步设置与真实掉电测试；R3 扩展 Postgres 等带 CAS/leader lease 的多节点 backend。
- Blob/transcript： immutable entries + artifact/blob store；大输出外置，数据库保存内容 hash/引用/生命周期，不在 event stream 回放无限制二进制。
- RPC：版本化 Schema/JSON framing + requestId/operationId/ownerEpoch + cancellation + queryOutcome + snapshot/resync；MCP 作为 ToolProvider Adapter，不让 MCP cancel 被误解释为效果停止。
- 执行隔离：优先独立 OS process/container sandbox，最小路径/网络/凭证能力；可信 in-process tools 有显式白名单，不作为默认多租户执行边界。
- Context：独立投影和摘要 checkpoint，保留原始审计版本，显式 redaction invalidation。
- Telemetry：trace/span + CommitSeq、Run/Task/Operation identities；结构化审计不能仅靠 stdout/LLM 消息文本。

## 6. 架构风险与初步缓解

| 风险 | 缓解 / 所需验证 |
|---|---|
| 外部 Tool 无 idempotency/queryOutcome | 明确 unknown/manual reconcile；策略默认 unsafe 不自动重试 |
| Intent 已 commit 而 Host 永久离线 | outbox 重试 + operator intervention；仅已验证 never-started 或幂等工具可安全重新投递 |
| Receipt commit 失败但外部 effect 已完成 | Host ledger 查询补写；没有 ledger 时 unknown，不盲目执行 |
| Worker split brain | DB CAS owner epoch + Host execution-side fence + lease renewal；跨主机抢占故障注入 |
| Approval 迟到/角色撤销 | approval TTL/scope/args hash/policy epoch + Host 前执行时再校验 |
| 历史编辑被旧摘要遮蔽 | ContextRevision/redaction epoch 检查 + invalidated summary 重做 |
| Provider/summary 重试重复计费 | 保存 ProviderRequestId，能查询则 reconcile，不能则报告 usage uncertainty |
| UI event 丢失或重复 | committed outbox + cursor + snapshot + bounded backpressure |
| Storage 断电丢最后 Intent | Durability tier 明示、fsync/WAL 真实故障注入、不能默认套用 SQLite NORMAL/JSONL marker |
| MCP server 无法取消 | Server capability declaration、deadline/unknown outcome、隔离进程终止但不宣称 rollback |
