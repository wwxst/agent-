## 3. 比较得出的工程判断（非最终设计）

- Claude 可借鉴 Remote Host call ledger、ranNothing/late correction、PermissionBroker、SSH seq/offset adoption；其服务端 ledger durability、V5 后端、renderer 恢复仍未知，SSH 持久 barrier 有 fail-open 分支。
- Pi Core 可借鉴小型内存 Loop、事件 await 屏障、原始顺序 ToolResult；但本身没有 durable task、强制权限与远端 Host。
- Pi Coding 具有可扩展的 TUI/Print/RPC、MCP 间接曝光与 JSONL 会话树；但默认不是强制 per-tool 审批，Project Trust 非 sandbox，也不提供 Durable Task intent。
- Pi Durable 最值得借鉴的是 checkpoint phase、owner DAG、Submission requestId、ToolTask execute intent、commit-derived events；但 Provider summarize 可重复请求，Compaction 与历史编辑有明确上游测试中的一致性缺口。
- Chord 可借鉴 TypeBox contract、principal/revoke、root/Ref lease、bounded state reset、processLock；但 RPC link 不 resume、in-flight effect U、process lock 不是 Task fencing。

**结论：** 取消≠终止≠副作用撤销；Session 历史恢复≠Task/Host/Tool 恢复；atomic commit≠断电持久性≠跨进程 owner≠external exactly-once。

## 4. 目标系统需要单独验证的属性

外部 operation ID / Host effect receipt/unknown outcome；Storage fsync/WAL 与断电；两个 worker 的 owner epoch/fence；审批回调迟到与权限撤销；Compaction summary input revision/redaction epoch；UI snapshot/cursor/reconnect；Provider retry billing/idempotency。所有这些**尚未做端到端动态验证**，必须列入后续验收矩阵，绝不能当成已具备保证。
