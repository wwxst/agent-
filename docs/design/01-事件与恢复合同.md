# 事件存储与恢复合同

> 推荐设计。事件名、表结构及 API 均需在重建源码前通过 ADR 确认。

## 一、权威事件日志

至少包含 Session ID、会话内单调序列号、不可重复事件 ID、Turn/ToolCall 关联、时间和结构版本。事件采用 **append-only** 语义；Snapshot/Checkpoint 只能加速重建，不能覆盖事实。写入必须使用 CAS/事务阻断并发竞态。

## 二、分离五类确认

| 阶段 | 代表什么 | 不代表什么 |
| --- | --- | --- |
| Command ACK | 命令已被持久接收 | Turn 已开始 |
| Turn admission | 轮次已获入场 | 模型已完成 |
| Tool Intent | 执行请求已经冻结并留痕 | 宿主实际执行 |
| Host STARTED | 宿主接手/开始执行 | 外部结果已确定 |
| Receipt | 宿主报告执行结果和证据 | 任意外部系统绝对 exactly-once |

## 三、工具执行不可知窗口

持久 Intent → Host 执行 → 可信收据之间仍存在崩溃窗口。若无法独立证明结果，应标记 `outcome_unknown` 并阻止非幂等重试；可通过可信宿主账本、目标系统幂等键或人工审核消除歧义。对账是**证据判断**，不是自动重试机制。

## 四、读写分离与事件投影

- 读历史时验证 Session 身份、事件连续性、版本与终态。
- 模型上下文可压缩和重排可见消息，但原始 Tool Outcome 与收据不可删除。
- 并行工具应及时按完成时序写入可信收据；模型可见结果按 ToolCall ID 和原始顺序重建。
- 客户端按事件游标重放并去重，不可用“流断开”推断 Turn 完成。

## 五、必须覆盖的故障

并发写冲突、重复 ACK、部分 append、Host 崩溃、超时、Lease/权限撤销、截断模型响应、Checkpoint 来源不匹配、未知副作用、事件模式迁移和文件系统写入不完全提交。
