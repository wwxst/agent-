# 客户端协议与验收原则

> 规范草案。**当前仓库没有 API 服务、CLI 或可运行测试**；以下是以后重建实现的最低验收要求。

## 客户端与命令

客户端通过经过身份验证的控制面提交创建 Session、Turn、Steer、Cancel 和 Approval 等命令。写命令带幂等键及期望版本；服务端绑定会话身份与权限。命令确认（ACK）只说明持久接受，不代表工具已完成。

## 事件消费

事件流应支持 `sessionId + afterSeq` 游标重放和去重。实时模型增量可以容忍丢失，但最终终态、工具收据与授权决策必须可从持久事实中查询。订阅断线不应导致第二次执行。

## 错误分类

区分非法请求、身份缺失、权限拒绝、版本冲突、Session Busy、租约失效、预算耗尽、模型流错误、工具拒绝、工具结果未知、恢复阻断。不要把这些全部映射为同一种“失败”。

## 验收矩阵

| 维度 | 核心验证 |
| --- | --- |
| Agent Loop | 正常结束、截断、重复 ID、非法参数、步数预算 |
| Provider | SSE 乱序/丢失/停止、工具部分参数、Usage 缺失 |
| Tool Host | 独立授权、越权拒绝、隔离能力缺失、子进程失联 |
| EventStore | CAS 竞争、崩溃恢复、重复命令、游标重放 |
| Lease | 旧执行者被隔离、失权后不启动新工作 |
| Outcome | 收据缺失保持 UNKNOWN、不盲重试 |
| Context | 来源校验、摘要回放、调用顺序稳定投影 |
| Extension | 不可越权、预算继承、取消与卸载一致 |
| Linux 隔离 | namespace、cgroup、seccomp、文件与网络实测 |

凡未在锁定版本与真实环境运行的测试，均标注**未验证**；历史 CI 结果不能视作新实现通过。
