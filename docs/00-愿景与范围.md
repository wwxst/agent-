# 00 · 项目愿景与范围

> 状态：v0.1 设计草案｜日期：2026-10-24｜实现状态：尚未开始

## 一、项目定位

本项目要开发一套**自主实现、可嵌入、与模型无关、与执行宿主解耦**的 Agent 内核。不是为 Pi、Codex、Claude Code 包一层接口，也不是把三个项目的源码拼接起来；而是借鉴其公开架构思想，由本项目自行定义协议、状态机和实现。

目标消费者包括 Web、CLI、桌面端、自动化服务。现有 `agent-web` / `agent-cil` 的集成属于未来适配任务；在审阅现有代码前不得宣称接口已经兼容。

## 二、核心原则

1. **内核自主**：核心 Loop、Session/Turn、Tool Registry、Context、Policy 和事件协议由本项目拥有；不得在核心路径中实例化 Pi/Codex/Claude Code 运行时。
2. **模型可替换**：Provider 把不同厂商的增量输出统一成规范事件；切换模型不应改 Agent Loop。
3. **宿主可替换**：内核只请求工具执行能力；权限验证、进程/文件隔离和副作用实际执行归 Tool Host。
4. **状态可恢复**：先持久化关键状态，再执行副作用；程序崩溃后不能静默重复文件删除、推送或导出。
5. **客户端无关**：客户端消费版本化事件流，不能绕过 Kernel 直接驱动内部状态。
6. **安全优先**：模型文本、仓库内容、网页、工具响应均是不可信数据；模型提出的操作必须经过独立策略授权。
7. **先正确再复杂**：优先单 Agent、单执行节点、少量工具；多 Agent、分布式能力要在事件与权限基础稳定后建设。
8. **可测与可观测**：确定性测试重放每一种状态转换；清晰追踪 Turn、Step、ToolCall 和审批决定。

## 三、参考来源与借鉴边界

| 公开项目 | 借鉴什么 | 不做什么 |
| --- | --- | --- |
| Pi Agent | 可理解的执行循环、模型事件标准化、工具注册与流式处理 | 不运行 Pi SDK 作为本项目核心 |
| OpenAI Codex | Session/Turn/Item 模型、事件流、审批、执行环境隔离与上下文预算 | 不复制其产品专用协议为唯一对外接口 |
| Claude Code | Hooks、Skills、子任务、权限策略和可扩展机制 | 不绑定 Claude Code CLI/SDK 为唯一执行器 |

这是设计参照清单，不是性能或源代码血缘判断。研究后需要为每个重大取舍补 ADR、测试与安全评估。

## 四、MVP（v0.1）要做到什么

- 创建会话；提交 Turn；流式接收文本、工具调用、审批、完成及失败事件。
- 支持至少两个 Provider 适配方案；统一增量解析和错误语义。
- 具备循环上限、Token/时间/工具调用预算、可取消性和超时。
- 工具：Read、Glob、Grep、Write、Edit、Bash（由受限 Tool Host 提供）。
- 每个工具调用都有唯一标识、参数校验、可见的审批决策与结果记录。
- 使用持久 Event Journal 恢复 Session 状态，并支持断线按序号回放事件。
- 使用最小权限隔离执行高风险操作；无可用隔离环境时默认拒绝高风险执行。
- 覆盖正常路径、拒绝、超时、取消、崩溃、重试和恢复的测试。

## 五、暂不承诺

插件商店、跨机器调度、复杂多 Agent 协商、完全自动化部署、IDE 全功能、视频时间线编辑器、无限长历史、零重复副作用、任何模型都保证相同行为——以上都不属于 v0.1 的交付保证。

## 六、成功标准

最基本验收情景：

1. Agent 读取一个真实测试工作区、修改文件、执行测试并返回摘要。
2. 工具需要审批时，暂停且不会抢先执行；审批拒绝有可追踪事件。
3. 客户端断开又重连时，按游标补齐事件，无需启动第二个 Turn。
4. 高风险工具执行前发生重启，系统识别为待确认或不确定，而不是盲目重放。
5. 相同场景在至少两种 Provider 上通过协议兼容测试（不要求自然语言结果完全相同）。
