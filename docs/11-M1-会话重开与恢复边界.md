# M1 增量：会话重开与恢复边界

> 状态：已实现「完整终态会话重开」的最小内核接口并配有确定性测试；**尚未实现持久化存储、故障自动恢复、跨进程单写者协调或副作用重放**。

## 设计目标

M0 的 `AgentKernel` 只能识别该实例调用 `createSession()` 创建的会话。即使后端换成持久 EventStore，新进程也不能继续读取/追加旧 Session。

第一步新增 `openSession(sessionId)`：**只重建内核进程内的会话游标，不重新调用模型或工具，也不推断外部副作用是否完成。** 这是建立 SQLite 与跨进程恢复能力前必须解决的重开入口，并不等价于完整 M1。

## 已实现的不变量

1. `openSession()` 只接受首条为 `session.created` 的已有日志。
2. 事件按 `sessionId`、从 1 开始的连续 `seq` 校验；重复创建会话、缺失 `turnId`、并行交叠 Turn、在 Turn 之外的事件都拒绝。
3. 已结束的 Turn（`turn.completed`、`turn.failed`、`turn.cancelled`）可被重开；新 Turn 按既有末尾序列号比较追加。
4. 如果最后仍有 `turn.queued` 或后续未终结的 Turn，返回 `RECOVERY_REQUIRED`，不产生补偿事件，不自动重发 ToolCall。
5. 同一 `AgentKernel` 实例的 `createSession/openSession` 使用内存准入保留，拒绝同 ID 并发开启。
6. 整个读取/校验完成之前不安装会话游标；失败不会让该 Session 成为可运行状态。

## 调用示例

```ts
// 持久化 EventStore 接入后可由新进程调用；下例仅展示协议。
const kernel = new AgentKernel(eventStore, provider, tools);
await kernel.openSession('existing-session-id'); // 只读校验，不执行任何旧工具
const result = await kernel.runTurn('existing-session-id', '下一条用户消息');
```

当 `openSession` 抛出 `RECOVERY_REQUIRED` 时，运营侧必须先调查历史 Tool Intent、实际执行回执和人工恢复决议；**不得在异常处理里循环自动重试旧 Turn**。目前尚无恢复操作 API，应该保持停机保护。

## 明确的安全边界

- `MemoryEventStore` 仍是单进程内存日志，重开测试复用同一个内存存储对象；无法证明重启、断电或 SQLite 崩溃恢复。
- `expectedSeq` 仅保护一次 compare-and-append；这并不建立跨进程分布式租约，两个 Kernel 实例并发操作同一 Session 仍需后续单写者协调。
- 目前没有 Tool Intent/Receipt 事务，也没有确认过的副作用，因此未决 Turn 的情况只能拒绝，无法自动识别「已成功但未写回结果」。
- 没有事件 hash 链或磁盘校验和；现有完整性校验是结构和顺序的逻辑校验，不是反篡改证明。
- 存储层若不保证 `append` 原子性和 `read` 一致快照，本入口的正确性保证不成立。

## 验证

`tests/kernel.test.ts` 新增 4 项：重开已完成会话并连续追加、未终态拒绝且日志不改动、损坏日志拒绝、重开并发排他。GitHub Actions 运行 Node 22 的 TypeScript 严格检查和测试，验证结果以具体 workflow run 为准。
