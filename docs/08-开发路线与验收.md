# 08 · 分阶段开发路线与验收标准

> 状态：设计草案。以下是开发顺序与验收门槛，不是日期承诺；目前所有阶段均未开始实现。

## 一、开发策略

先冻结**最小可验证合同**，再实现模型适配和 Loop；不要一开始同时开发 Rust Host、插件市场、分布式 Agent 和全套桌面 UI。

每个任务必须满足：先阅读规范 -> 提交设计影响 -> 添加相关测试 -> 实现最小功能 -> 执行验证 -> 报告结果与未覆盖风险。

## 二、阶段划分

### M0：协议与工程底座（未开始）

交付：
- 仓库目录、包管理、CI、类型检查、测试框架；
- contracts 包，Session/Turn/ToolCall/Event 类型与错误模型；
- EventStore、Policy、Provider、ToolHost 的接口及 Fake 实现；
- 首份 ADR 与安全边界文档。

验收：离线单元测试可构造 Session、持久化/重放事件，非法状态转换被拒绝。

### M1：独立单 Agent 内核（未开始）

交付：
- 自研 Agent Loop，不依赖 Pi/Codex/Claude Code 运行时；
- 两个 Provider Adapter（可用真实 Provider 或认证兼容测试服务验证）；
- Read/Glob/Grep 和受限 Write/Edit；
- ToolCall 参数验证、预算限制、取消；
- 命令接口和基础事件流。

验收：示例工作区的文件阅读、修改和测试任务能结束；所有工具调用有事件与结果映射；流中断不执行未完成 ToolCall。

### M2：可靠性和安全（未开始）

交付：
- Bash 隔离宿主、审批系统、幂等控制；
- 事件快照、断线重放、失败恢复；
- 上下文窗口管理和压缩；
- 故障注入与执行可观测性。

验收：拒绝权限时 0 次执行；审批不可跨调用复用；重启不会静默重放不确定副作用；断连不会重复提交 Turn。

### M3：扩展与多 Agent（未开始）

交付：
- Hook、Skill、MCP 统一接入；
- 子 Agent 独立上下文、任务树、并发预算；
- 子任务取消、结果回传、权限继承规则。

验收：子 Agent 无法越权；超时和取消可传播；任何插件不能直接绕过 Tool Host 执行高风险操作。

### M4：远程与领域工作流（未开始）

交付方向（需要先做 ADR）：远程 Worker、产物管理、浏览器、FFmpeg、媒体预览/人工确认等。

验收：不同宿主之间不会误执行；有进度、失败恢复和工件来源；危险媒体改写需要明确授权。

## 三、工程质量门槛

| 类型 | 必须验证 |
| --- | --- |
| Agent Loop | 确定性 Fake Provider、重入、取消、循环与工具上限 |
| Provider | 不同流式事件顺序、非法参数、限流、超时、用量 |
| EventStore | 并发冲突、去重、游标重放、断电恢复 |
| Tool Host | 路径逃逸、命令隔离、超时、输出边界 |
| Policy | 参数指纹、审批过期、能力撤销、跨租户调用 |
| Context | 截断策略、压缩失败、任务关键事实留存 |
| API | 权限隔离、幂等键、错误码、断线重新订阅 |
| Subagents | 预算继承、并发上限、取消与结果交付 |

不能只依靠编译或 AI 自评证明正确。测试命令实际未运行时必须记录 NOT RUN。

## 四、每个 PR 的完成定义（DoD）

1. 修改范围和预期行为明确，必要时有 ADR。
2. 测试覆盖变化路径和至少一个失败路径；涉及副作用则有故障注入或恢复测试。
3. 类型检查、单元测试、适用的集成测试通过。
4. 对风险与权限边界进行人工复核。
5. 文档和变更记录同步。
6. PR 包含“变更内容 / 运行命令及结果 / 未运行项目 / 已知风险”。
7. 未经授权不直接推送 main、不覆写他人变更。

## 五、研发优先级与不做项

- **先做**：协议、不变量、内核 Loop、事件/工具契约、权限审计。
- **随后做**：端到端安全和恢复、上下文压缩、多个 Provider。
- **最后做**：视觉交互、插件市场、分布式任务、丰富的专业 Agent。

衡量进展看的是测试可证实的行为，不是累计代码行数、Token 消耗、功能数或分支数量。
