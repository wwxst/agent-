# 08 · 开发路线与验收标准

> 文档状态：持续维护。本文区分已落地能力、进行中的增量和未实现目标；阶段名称不代表生产就绪或自动获得安全保证。最后核对：2026-10-31。

## 一、开发原则

项目按“可验证合同 → 最小实现 → 故障测试 → 安全边界复核 → 文档同步”的顺序推进。

- 正确性、数据安全和权限边界优先于功能数量与交付速度。
- 以代码和实际测试为准；设计文档、分支记录或静态检查不能替代运行证据。
- 不确定的外部副作用不得自动重放，不承诺无法证明的 exactly-once。
- 新能力默认关闭或显式启用；安全环境不满足时应拒绝启动，不得静默降级。
- 任何阶段的“已实现”都不等于生产就绪，必须同时阅读本节的限制与验收证据。

## 二、当前实现概览

以下状态按仓库当前 `main` 的代码与文档记录整理。具体能力仍应以对应测试和实现为准。

| 模块 / 阶段 | 当前状态 | 已有内容与边界 |
| --- | --- | --- |
| M0 内核基础 | 已实现 | contracts、Kernel Core、Provider 抽象、Tool Scheduler、内存事件存储及 CLI 基础；有离线确定性测试。 |
| M1 会话与持久化 | 已实现增量 | Session 重开校验、SQLite WAL 事件日志、Writer Lease/Fencing、托管 Runner、Intent/Receipt、双账本对账和人工复核记录。未决执行不自动恢复或重放。 |
| Provider 与 CLI | 已实现基础链路 | OpenAI Chat Completions 与 Anthropic Messages 流式适配、工具目录快照、用量/预算准入和受限文本 CLI；不代表所有模型/账户的计费端到端已验证。 |
| M2 控制与上下文 | 已实现增量 | Command Inbox、Steering、Context Checkpoint、Command Dispatcher、本地控制面、持久凭据轮换撤销和执行期间授权重检。控制面不是生产级远程网关。 |

### 当前明确未完成的事项

- 独立 Worker cgroup 在真实可委派 Linux 环境中的正向验收。
- 完整、最小权限的 seccomp allowlist 与跨架构策略。
- SQLite 数据库主体写权限隔离，以及所有工具默认强制进入安全 Host。
- Reviewer 生产鉴权、高风险能力审批和受控 Recovery 修复流程。
- 真实计费 API 的端到端联调与覆盖更多 Provider/模型的兼容验证。
- 具有外部副作用的工具及其幂等、撤销和人工确认语义。
- Subagent、MCP、Skills、桌面/Web API 与远程 Worker 的完整产品化。

在上述缺口关闭前，不得将当前仓库描述为生产级、全功能或默认安全隔离的 Agent 平台。

## 三、后续开发阶段

阶段是规划维度，不覆盖第二节中的实际状态。

### P1：内核正确性与接口稳定

- 固化 Session/Turn/Step/Event 的状态转换合同。
- 明确 Provider 流事件、工具调用、取消和终态之间的边界。
- 检查所有公共接口的错误模型、输入校验和兼容策略。
- 为关键不变量补充正向、拒绝、并发和崩溃测试。

验收：非法状态转换被拒绝；取消不会伪造成功终态；流中断不会执行未完整确认的工具调用；接口变更同步更新调用者和测试。

### P2：持久化、恢复与审计闭环

- 完成双账本证据模型和审核者身份的可信绑定。
- 定义未决 Turn 的人工处置、修复授权和审计流程。
- 保持恢复操作可审计、可验证、默认不自动重放未知副作用。
- 对 SQLite 并发、进程崩溃、损坏和迁移进行故障注入。

验收：恢复决策有完整证据；重复命令不会重复执行；未知结果保持阻断；审核记录不能被普通执行路径伪造或覆盖。

### P3：工具执行安全边界

- 完成独立 Worker cgroup 的真实正向验收。
- 评审 seccomp 策略、架构限制、文件系统挂载和网络边界。
- 明确数据库写入权限、临时目录、凭据与日志的隔离方式。
- 将安全 Host 的使用范围、默认策略和拒绝原因写入接口文档。

验收：不满足安全条件时启动失败且不降级；真实探针验证进程、文件、网络和资源边界；危险能力需要明确授权；测试覆盖伪造身份、竞态和异常退出。

### P4：扩展能力

- 设计 Subagent 的身份、预算、上下文和取消传播。
- 定义 MCP、Skills、Hooks 和插件的能力声明及生命周期。
- 所有扩展能力必须经过 Kernel/Host 的统一策略检查。

验收：扩展不能自行授予权限、绕过工具执行入口或污染其他 Session；超时、取消、预算耗尽均有确定语义。

### P5：客户端与远程工作流

- 在稳定协议之上建设 Web、桌面和远程 Worker。
- 明确认证、Session 授权、事件游标、断线重连和工件来源。
- 浏览器、媒体和其他领域工具按风险分级接入。

验收：客户端不能越权；断线重连不重复执行；远程 Worker 身份与能力可验证；危险操作具备明确授权和审计记录。

## 四、工程质量门槛

| 范围 | 必须覆盖的验证 |
| --- | --- |
| Kernel / 状态机 | 合法与非法状态转换、重入、取消、循环上限、终态不可逆 |
| Provider | 流事件乱序/截断、非法工具参数、限流、超时、用量与预算 |
| EventStore | 并发冲突、事务原子性、去重、游标重放、崩溃重开 |
| Lease / Runner | 过期租约、Fencing Token、续租失败、旧持有者隔离 |
| Tool Host | 参数与身份校验、超时、输出边界、进程退出、路径与挂载边界 |
| Policy / Control Plane | 凭据轮换撤销、Session 权限、授权重检、审计失败时拒绝放行 |
| Context | Checkpoint 来源验证、压缩失败、未决状态拒绝、原始日志保留 |
| API / Inbox | 身份认证、幂等指纹、权限隔离、断线重试与错误码 |
| Linux 沙箱 | namespace、cgroup、seccomp、文件/网络探针和不支持环境拒绝 |
| 扩展能力 | 身份与预算继承、并发上限、取消传播、权限不可提升 |

## 五、每次变更的完成定义（DoD）

1. 变更目标、影响范围和兼容性明确。
2. 涉及架构、数据格式或安全边界时，新增或更新 ADR。
3. 测试覆盖成功路径、拒绝路径和适用的故障路径。
4. 实际运行类型检查、相关测试及必要的集成验证，并记录真实结果。
5. README、文档索引和受影响设计文档同步更新。
6. PR 说明变更内容、验证命令与结果、未运行项目和已知风险。
7. 不在未获授权时直接修改 `main`、强推或合并。

## 六、常用验证命令

仓库要求 Node.js >= 22.16.0：

```bash
npm install
npm run check
npm test
```

`npm test` 会先执行 TypeScript 构建，再运行 `dist/tests/*.test.js`。Linux 沙箱、cgroup 和 seccomp 测试需要满足对应内核与宿主环境条件；环境不满足时应明确记录为跳过或未运行，不得将其描述为通过。

## 七、文档维护规则

- 新功能先确认实际代码入口和测试，再更新对应设计文档。
- 文档中的“已实现”“已验证”“生产可用”是不同结论，必须分别举证。
- 历史研究材料保留在 `docs/research/`，当前架构决策放在 `docs/adr/`，实现记录按主题维护在 `docs/`。
- 不删除仍被代码、测试、ADR 或其他文档引用的文件；归档前先检查引用关系。
- 文件编号冲突时采用新编号并在索引中标明，不通过批量重命名制造无意义 diff。
