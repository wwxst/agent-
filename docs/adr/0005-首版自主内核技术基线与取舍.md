# ADR 0005 · 首版自主 Agent Kernel 技术基线与四内核借鉴取舍

- 日期：2026-10-26
- 状态：**Proposed / 推荐采用；等待维护者批准，不是已实现或正式 Accepted**
- 决策范围：M0–M2 内核、存储、安全宿主与协议。M3/M4 只规定原则不冻结技术细节。
- 证据：[四内核总目录](../research/comparative/README.md) · [存储证据审计](../research/comparative/12-四内核执行与持久化证据审计.md) · [工具/权限比较](../research/comparative/13-工具权限与异常恢复对照.md) · [完整技术评审](../research/comparative/14-自研内核架构取舍正式评审稿.md) · [完成边界](../research/comparative/15-研究完成判据与剩余缺口.md)

## 背景

团队目标不是复刻/封装一套既有 Harness，而是构建独立的可信 Agent Kernel。Pi、Codex、Claude Code、DeepSeek Harness 已经研究到可识别运行时主链与不少异常/持久化边界，但动态 OS/崩溃测试尚未完成。需要先落地可测试的技术基线，避免无限期停留在文档讨论；同时不把尚未测量的可靠性标记为已保证。

## 决策提议（默认优先实施的方案）

### D1 · 独立的 TypeScript Kernel Core

用 TypeScript/Node 实现 Session/Turn/Step FSM、Provider Adapter、Context Admission、ToolCall Scheduler、Policy Root、EventStore Contract、公共协议。依赖方向从业务层指向 Kernel Contracts；模型 Provider 和扩展不得修改内部执行状态。

Rust **不作为首版 Kernel 的前置依赖**；将来如实际 OS 沙箱/系统资源隔离、内存边界、崩溃安全或吞吐需要，可单独引入 Rust/原生 ToolHost，不用重写状态机。

### D2 · 可信状态机与 Scope 插件分离

- 核心不可由普通扩展热替换：FSM 转移、Event Journal Commit、硬预算、Policy Deny 根、Tool Host 执行令牌验证、外部副作用恢复规则。
- 可按 Agent/Task Scope 挂载：模型 Provider、上下文贡献器、工具适配器、Skills、MCP、非权威 Hook、客户端 Transport。
- 插件卸载不改变已运行 ToolCall 的工具版本和许可；必须 drain 或明确终结已入场调用。

### D3 · 本地首版用事务型 SQLite 事件日志

- SQLite WAL、单主写者；每次关键命令接受、审批与 Tool Intent 使用数据库事务+状态版本；
- `(sessionId,commandId)`、`(sessionId,seq)`、`toolCallId` 等唯一键保护去重；
- `sessions/events/commands/tool_intents/tool_receipts/approvals/outbox/snapshots` 明确分表；
- 关键写入使用严格同步配置并经故障测试；不把普通 `flush` 函数名当物理落盘保证；
- 模型历史、搜索/列表、会话分支投影、JSONL 导出都是可重建视图，不能改写已提交事实。

只读客户端可订阅 SSE，写请求经 Kernel Command Admission；以后如需要多 Host/分布式，再独立 ADR 决定 PostgreSQL / Lease / Queue。

### D4 · 独立工具宿主 + 不可绕过的权限根

- Tool Host 在 OS 隔离环境中执行文件/Shell/网络/媒体工具；
- 高风险工具的批准绑定 `toolCallId/argsHash/toolVersion/policyVersion/hostId/expiresAt`；
- 内部特权字段由 Host/Policy 签发，不允许模型 JSON、Plugin 或前端直接伪造；
- 强制沙箱要求如果无法满足就 fail-closed；没有真实沙箱的 M0/M1 默认不开放危险 Shell；
- Tool Host 返回有稳定 ID 的执行收据；模型可见 ToolResult 和 Hook 可修改的内容不能覆写这张收据。

### D5 · 有序、保守的工具调度

M1 采用 **S2：独占屏障 + 明确只读工具并发 + 按 ToolCall 原序提交结果**；输入 Schema/审批/Guard 必须在工具 Body 运行前完成，未知分类默认独占；每步冻结 ToolSet、Provider、Policy 与 Context。

不立即构建跨进程读写集冲突图（S3）。待能正确处理符号链接/路径/跨 Host 锁后另行 ADR。

### D6 · Cancel / Interrupt / Unknown 独立状态

- `InterruptRequested` ≠ `TurnAborted`；
- `CancelRequested` ≠ `ToolCancelled`；
- `SIGKILL`/CLI stdout 关闭 ≠ 外部副作用确认不存在；
- ToolCall Intent 已持久化、Host 有可能执行但回执丢失时进入 `OutcomeUnknown`；
- Non-idempotent/Unknown 工具不因重启/模型恢复而自动重试；
- Subagent 仅获父任务能力子集，单独预算、TaskID 和可审计资源释放。

### D7 · 自主、版本化协议

首版 HTTP+SSE + CLI adapter：

- 命令请求有 `requestId/sessionId/expectedVersion/idempotencyKey`；
- DurableEvent 有 `eventId/sessionId/seq/schemaVersion`，必须先持久提交再广播；
- 实时 Token Delta、进度事件不承诺可持久重放；
- `steer` 带 expectedTurnId；`cancel` 与后台 `stopTask` 分开；
- 未来 SDK/桌面 IPC 只是 Transport 层，不要求 Claude SDK ProcessTransport 作为核心依赖。

## 对四项目的取舍

| 参考内核 | 借鉴 | 不采用/须改进 |
| --- | --- | --- |
| Pi | 小型双层循环、Steer/FollowUp、Session Tree、Compaction CutPoint | 进程内数组或普通 JSONL 不是副作用事务 |
| Codex | StepContext、ToolRouter、ApprovalAction、Rollout/Index 职责分离 | 不照搬巨型 Rust Core；`File.flush` 不等于全部掉电保证 |
| Claude Code | StreamingToolExecutor、复杂审批链、后台 Shell/Subagent、SDK 控制生命周期 | 不直接依赖专有 CLI；中断不等于副作用撤销 |
| DeepSeek | Scoped Registry/Profile、PreExecute/Guard、批次独占屏障、日志投影、恢复语义修复 | 普通插件不能接管可信根；Live Event append 不能代替事务提交 |

## 为什么不是其他方案？

- **全 Rust**：可以实现，但第一阶段抽象验证速度较慢，不是用 Rust 就自动有正确事务和沙箱。
- **全 JS 同进程 Shell**：简单，但未经隔离的工具可越过 Policy 与进程边界，不适合作为高风险工具默认模式。
- **JSONL 唯一权威**：易人工查看/分支，但我们的任务需要命令去重、审批和 Intent 原子更新；事务型 SQLite MVP 更直接。以后可以导出 JSONL。
- **全部能力皆热替换插件**：高度灵活，但信任根和恢复准则容易被任意扩展绕过。
- **工具全部串行**：最安全保守但非必要损失读工具并发；可作为初始测试模式，但 S2 可在可信准入后逐步启用。
- **立即全局资源冲突图**：收益未知、实现成本高、路径竞态难证明，保留未来复审。

## 需要什么证据才能转 Accepted

1. M0 真实代码的 FSM/Provider/ToolScheduler Fake 测试、异常和重放通过；
2. SQLite WAL 的事务回滚/进程崩溃试验、ACK 前持久提交实测；
3. Tool Host 隔离失败时拒绝执行与参数指纹审批准入测试；
4. 两读一写工具的 S1/S2 调度正确性和吞吐比较；
5. Context 摘要不覆盖真实 Tool Intent/Receipt，且压缩失败能恢复；
6. 环境支持/非目标平台和 OS 安全限制有清晰说明；
7. 维护者批准后将本 ADR 状态从 Proposed 改为 Accepted；没有这一流程不能把推荐决策写成既定产物。
