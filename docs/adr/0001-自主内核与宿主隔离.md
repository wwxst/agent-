# ADR 0001 · 自主实现内核并分离工具宿主

- 状态：提议（待项目维护者接受）
- 日期：2026-10-24
- 影响范围：项目架构、代码依赖、权限和交付路线

## 背景

项目希望吸收 Pi Agent、OpenAI Codex 与 Claude Code 的公开设计经验，构建可自主维护的 Agent 内核。直接嵌入现有 Agent SDK 虽可加快起步，但会使核心的执行状态、权限、事件语义和扩展接口受到上游约束。

同时，Agent 决定要调用的工具和操作系统真正执行的副作用是两个风险等级不同的责任域。用提示词来代替操作系统安全边界不可接受。

## 决策提议

1. 自主实现 Agent Loop、Session/Turn FSM、Context、ToolCall 调度和持久事件合同。
2. 不把 Pi、Codex 或 Claude Code 的 Agent Runtime 作为核心执行依赖；它们可以用作设计研究对象或日后由独立 Adapter 调用的外部专业服务。
3. Provider Adapter、Tool Host、EventStore、Policy Engine 都通过本项目拥有的稳定接口连接。
4. Kernel 本身不进行高权限文件、Shell、网络操作；Tool Host 强制实施审批及隔离。
5. 先构建单节点、确定性、可恢复的 MVP；再逐步扩展多 Agent 和远程执行。
6. 将事件日志、工具调用身份、授权记录作为一等对象，以支撑可靠恢复和审计。

## 备选方案

| 方案 | 优点 | 放弃理由 |
| --- | --- | --- |
| 直接嵌入 Pi SDK | Agent Loop 少写很多 | 与“自主实现核心执行引擎”的主要目标不一致 |
| 将 Codex App Server 作为 Kernel | 安全和工程能力现成 | 核心协议与执行状态由外部引擎主导 |
| 基于 Claude Agent SDK | Hooks、Skills、Subagents 成熟 | 产品内核依赖外部特定运行时与能力结构 |
| 完整 Rust 单体 | 类型安全、原生能力 | 初期跨模块成本高，且语言本身不等于安全沙箱 |
| 自研 Kernel + 独立 Host | 代码控制权、可替换、可测 | 自己承担 Agent Loop、安全、持久化、测试成本 |

## 后果

**积极影响**：能够统一 API、模型、工具和客户端，独立演进状态机和插件协议。

**成本与风险**：需要独立实现流式 ToolCall 解析、上下文预算、取消竞态、审批、崩溃恢复与安全执行；首个可用版本不应追求“现成 Agent 的全部功能”。

## 必须满足的验收

- 更换 Provider 不修改核心状态机。
- 无真实操作系统隔离时不能执行高风险工具。
- 外部副作用状态不确定时不会盲目重试。
- 事件存储可回放、Session/Turn 状态转换可测试。
- 前端与工具宿主都不能绕开权限引擎直接改变 Turn 状态。

## 适用方式

只有在维护者审阅并接受此 ADR 后，才把它升为 Accepted。代码实现与后续 ADR 必须保持同步；文档本身不是已实现的证据。
