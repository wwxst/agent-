# ADR 0002 · 能力组合与不可绕过的内核边界

- 状态：提议（待维护者审阅）
- 日期：2026-10-24
- 研究来源：DeepSeek Harness / Cordis

## 背景

DeepSeek Harness 演示了通过服务、事件、可逆注册与配置 Profile 将模型、工具、Session、Loop、UI 等组件自由组合的方案。此思路可改善自研 Agent Kernel 的扩展性，但如果让普通插件替换安全根、状态机和事件提交路径，可能损害跨任务恢复、审批一致性与执行审计。

## 决策提议

1. **保留可信内核**：Turn 状态转换、预算硬上限、事件日志提交、工具执行意图/结果、审批授权根由 Kernel 可信模块持有，不作为普通插件的可热替换接口。
2. **能力外置、组合可替换**：Provider、Tool Adapter、ContextContributor、Skill、MCP、客户端 Transport、具体 Tool Host 可通过显式契约装配。
3. **每 Agent Scope**：每个注册拥有所有者与作用域；Global/Session/Agent/Task 只能按允许方向继承，子任务权限不能扩展父任务的授权。
4. **资源生命周期**：初始化采用准备—提交语义；错误回滚；卸载幂等，并在活动调用完成或显式取消后 drain。
5. **配置版本固定**：为 Turn/ToolCall 记录所使用的插件/Schema/能力集合版本；运行中的插件更新不得改变已经审批的工具实现或参数解释。
6. **事件双轨**：状态事实先持久化再广播；Token 与进度等临时增量通过另一通道发送，客户端要能在断线后恢复可验证的最终状态。
7. **安全与扩展分离**：插件注册和 Hook 允许减少权限，不允许越过 Tool Host 与 OS 级隔离；未验证沙箱不得承诺可执行不可信代码。
8. **MVP 保守**：v0.1 只支持静态注册和基本 Scope；动态热重载、可替换 Loop/Store、Profile 叠加配置属于后续阶段。

## 备选方案

| 方案 | 优势 | 缺点 |
| --- | --- | --- |
| 把所有模块做成可替换插件 | 组合自由度最大 | 难以保证安全、提交与恢复的一致性 |
| 完全固定单体内核 | 容易理解，状态集中 | Provider/Tools/业务能力扩展成本偏高 |
| 稳定可信内核 + 可组合能力层（提议） | 平衡可控性、扩展性与可审计性 | 需要严谨的接口版本和生命周期协议 |

## 公开观察与风险

- 官方架构文档：https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md
- Scoped Registration：https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/scope
- Agent Loop 限制：https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md
- 安全说明：https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md

DeepSeek 的 Agent Loop 文档记载活跃 Agent 在 Root shutdown 时末尾 turn/end 持久化可能缺失，以及默认无内建 Turn 预算。我们应将这些作为**专门防止重现的验收测试**，而不是沿用其当前行为。官方明确声明项目未经过安全审计。

## 验收门槛

- Provider 插件缺失或失败不会让 Kernel 改变状态机不变量。
- Plugin setup 部分失败后资源全部回滚，且旧 Provider 仍可工作。
- Active Turn 中更新/卸载插件不会改变正在执行的调用与审批语义。
- Scope 解绑不会删除或污染兄弟 Agent 的 Tool、Hook 或 Service。
- 已观察到终态事件后不能出现终态只在内存、日志未持久化的状态。
- 默认 Turn 步数/耗时/工具调用预算无法被插件绕过。
- 插件不能通过注册操作获得超出授予范围的文件/网络/Shell 权限。

## 后果

优点：未来可灵活组合 Coding、Browser、Media 等工作形态，并有更清晰的组件归属。代价：需要增加 Registry、Scope、生命周期和版本协商的工程成本，不能在 v0.1 过度投资“随时热插拔一切”。
