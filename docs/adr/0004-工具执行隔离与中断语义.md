# ADR 0004 · 区分工具执行隔离、用户中断、取消、超时和后台任务

- 状态：**提议（Proposed，待维护者决定）**
- 日期：2026-10-25
- 研究依据：[Claude Code Shell 执行实证研究](../research/claude-code/19-Shell实际执行与取消语义.md)、[沙箱策略映射](../research/claude-code/16-沙箱执行与策略映射.md)
- 影响范围：Kernel Turn FSM、ToolHost、Policy、任务产物、CLI/Web API、事件日志

## 一、问题

研究 Claude Code 2.1.88 可读源码发现：Shell ToolCall 实际经过 Schema/权限链、Shell Provider、可选沙箱包装，最终进入 child_process.spawn。取消原因 `interrupt` 与普通 Abort 具有不同处理，超时有自动后台化分支，进程退出也可能不代表所有后代副作用结束。沙箱本身还依赖平台支持、工具链、用户和管理设置。

如果自研 Kernel 只使用 `running/cancelled` 两种状态，或只传 `sandbox: boolean`，会在安全和恢复方面发生语义错误。

## 二、决策提议

### 1. 工具执行隔离是强合同，而不是 UI 标记

- 每个 ToolCall 提交 `IsolationRequirement`、ResourceCapabilities、ToolVersion、PolicyVersion 和 HostIdentity；
- 高风险工具默认要求经过验证的隔离；隔离无法建立则拒绝执行；
- 显式允许不受沙箱约束的操作需单独的审批凭据，包含风险、作用域、过期时间和操作者；
- Host 返回 `IsolationReport`：真正建立了什么限制、平台和策略版本；
- 只允许 ToolHost 签发已实施隔离的收据，Provider、Plugin、UI 不能自证 `sandboxed`。

### 2. 内部宿主字段不能来自模型请求

- 将模型 Tool Input 与宿主内部执行令牌分离；
- 模型输入经严格 Schema 校验、来源追踪、权限判断；
- 内部文件写入预计算结果、沙箱覆盖权限、宿主执行位置等由可信服务端创建，不接受模型生成的同名 JSON 字段；
- 任何 Hook 修改输入时，必须重新生成参数摘要并复核授权。

### 3. Interrupt 与 Cancel 语义分离

| 意图 | 语义 | 任务真实状态 |
| --- | --- | --- |
| `interrupt_turn` | 用户提出新指令或抢占交互焦点 | 某些工具可在明确批准后转后台继续 |
| `cancel_turn` | 请求取消本次 Turn 与仍受控的工具 | `cancel_requested` 不等于 `cancelled` |
| `stop_task` | 停止一个特定后台任务 | 只作用于该 Task ID，不默认为整个 Session 取消 |
| `timeout` | 超过预算或宿主执行时限 | 终止、转后台或失败由预先确定的策略决定 |
| `host_lost` | Worker/进程丢失联络 | 不可确认的外部副作用进入 `outcome_unknown` |

禁止将进程发出终止信号直接当作成功取消。所有终态需结合 Host Receipt 与实际执行状态提交。

### 4. 工作目录、工件与进程树边界

- 工具在运行前绑定工作区 ID、Host ID、规范路径及版本。目标路径消失时默认拒绝改写，不自动从已删除目录回退到父目录或进程当前目录。
- stdout/stderr 与最终工件存储在 Host 控制的受限目录；输出文件采用安全创建/访问方式、防符号链接攻击和大小配额。
- 前台进程已退出与后代进程完成区分；若宿主无法证明其资源/副作用终结，记录风险或结果未知。
- 任意 Bash/Shell 执行不可保证所有外部副作用 exactly-once，恢复前必须查询宿主收据或人工确认。

### 5. 事件与 API

建议事件：

```text
ToolCallValidated
ToolCallAuthorizationRequested / ToolCallAuthorized / ToolCallDenied
ToolCallIntentCommitted
ToolIsolationEstablished / ToolIsolationUnavailable
ToolExecutionStarted
ToolInterruptRequested / ToolCancelRequested / ToolBackgrounded
ToolExecutionSucceeded / ToolExecutionFailed / ToolOutcomeUnknown
ToolArtifactsFinalized
```

部分事件可合并为带字段的统一事件，但必须保留语义区分与完整关联 ID。服务端对外承诺的任何成功事件，必须先持久提交。

## 三、替代方案

| 方案 | 优点 | 放弃理由 |
| --- | --- | --- |
| 一个 `sandbox` 布尔值 + `cancelled` 状态 | 实现简单 | 无法表示真正隔离效果、迟到副作用和中断后台化 |
| 全部 Shell 默认无沙箱，靠模型与 UI 提示 | 快速实现 | 无实际 OS 安全边界 |
| 完全禁止所有后台任务 | 容易控制 | 不利于测试、编译、视频导出等长时工作；可作为 MVP 策略但非最终架构 |
| 强隔离合同 + 多状态任务执行（本提议） | 审计、恢复和扩展语义清楚 | 需要额外 Host、Receipt、测试和平台适配成本 |

## 四、验收门槛

- 强制沙箱时依赖缺失，Shell 执行次数为 0；没有无声降级。
- 模型恶意构造内部参数/沙箱绕过字段无法得到 Host 级能力。
- User Interrupt 不等于 Kill：明确后台化时工具仍可追踪，未明确允许时不自动继续。
- Cancel 发送成功不等于外部副作用回滚；未知情况进入 OutcomeUnknown。
- 同时发出取消与工具完成回执，通过持久状态版本产生唯一合法终态。
- 工作区失效不会在新目录继续写入；输出路径和工件引用无法跨 Session/Host 伪造。
- 任务输出无限增长时限额生效，删除/关闭遵守安全边界。
- 跨 OS 不支持的隔离能力明确标识 Unsupported，不伪装为相同安全水平。
