# 模块地图与依赖边界

> 本文是代码导航，不替代各模块的 API、设计文档和安全评审。目录与职责以当前源码为准；模块“已存在”不代表具备生产级安全保证。

## 一、仓库结构

```text
apps/
  cli/                     命令行应用入口
packages/
  contracts/               Kernel 与适配器共享的类型、事件和接口合同
  kernel-core/             Agent Loop、Session/Turn 状态机与事件投影
  model-providers/         模型厂商协议适配与流式事件转换
  tool-scheduler/          工具目录、调用预检、并发与执行编排
  event-store-memory/      内存事件存储适配器
  event-store-sqlite/      SQLite WAL 事件存储适配器
  session-leases-sqlite/   Writer Lease 与 Fencing Token
  session-runtime/         组合 Kernel、SQLite 与租约的托管运行入口
  tool-audit/              Kernel 侧 Tool Intent/Receipt 审计
  tool-host/               子进程 Worker、Host 台账与可选 Linux 隔离
  tool-reconciliation/     Kernel/Host 双账本只读对账
  recovery-review/         证据绑定的人工复核记录
  command-inbox/           持久 Command 接收与 ACK 幂等
  command-dispatcher/      Command 与 Turn 的持久绑定/分发
  steering-audit/          活动 Turn 指令队列与审计
  context-engine/          Context 准入、Checkpoint 与摘要投影
  control-plane/           本地身份、凭据和 Session 授权控制面
tests/                     单元、集成、故障与 Linux 环境测试
docs/                      中文架构、实现记录、ADR 与研究材料
m0/                        M0 阶段说明
```

## 二、运行主链路

典型托管调用关系如下：

```text
CLI / 上层调用方
       |
       v
ManagedSessionRunner
       |-- Writer Lease / Fencing
       |-- SQLite EventStore
       v
AgentKernel
       |-- Context Engine
       |-- Provider Adapter ----> 模型服务
       |-- Tool Scheduler
       |       |
       |       v
       |    Tool Host ---------> Worker / 可选 Linux 沙箱
       |
       |-- Tool Audit / Steering / Command / Checkpoint 审计
       v
SQLite 事件日志与执行账本
       |
       v
Tool Reconciliation / Recovery Review（只读对账与人工复核）
```

这是概念关系图，不代表所有模块都在每个入口中自动启用。具体入口的装配方式以调用代码和对应测试为准。

## 三、模块职责与边界

| 模块 | 应负责 | 不应负责 |
| --- | --- | --- |
| `contracts` | 稳定的数据类型、事件名称和跨模块接口 | 具体数据库、网络请求或工具副作用 |
| `kernel-core` | 状态转换、模型步骤、上下文投影和事件编排 | 厂商 HTTP 协议、SQLite SQL、OS 沙箱实现 |
| `model-providers` | 请求序列化、SSE 解析、Provider 错误与用量映射 | 执行工具、写入 Session 日志或授予权限 |
| `tool-scheduler` | 工具预检、目录快照、调用顺序和并发屏障 | 自行扩大工具权限或绕过 Host |
| `event-store-*` | 实现 EventStore 持久化接口 | 决定 Agent 状态机语义 |
| `session-leases-sqlite` | Lease、续租、释放和 Fencing 校验 | 代替工具 Host 验证副作用执行 |
| `session-runtime` | 将 Kernel、Lease、SQLite 和授权 Guard 组合为托管入口 | 作为操作系统级强制终止或完整沙箱 |
| `tool-host` | 子进程执行边界、Host 侧账本、Worker 身份/隔离检查 | 由调用方自报信息替代内核侧验证 |
| `tool-audit` / `tool-reconciliation` | 记录执行意图/收据并对账 | 对不确定副作用自动重放 |
| `recovery-review` | 对证据快照进行人工复核留痕 | 未经独立授权直接恢复或重试 |
| `command-inbox` / `command-dispatcher` | 接收幂等、ACK 和 Command→Turn 绑定 | 将 ACK 等同于执行成功 |
| `control-plane` | 身份凭据、授权判定和审计 | 未经部署配置成为公网生产网关 |
| `context-engine` | 上下文预算、可信摘要和 Checkpoint 校验 | 删除或篡改原始事件证据 |

## 四、依赖方向约束

1. `contracts` 是共享合同层，不依赖任何具体业务模块。
2. `kernel-core` 依赖合同和抽象能力，不直接耦合具体 Provider HTTP 或 SQLite 实现。
3. Provider 只负责协议适配；不得执行 ToolCall 或修改 Session 持久状态。
4. Scheduler 只做执行编排；实际 Host 必须再次验证身份、租约、参数和权限。
5. SQLite、进程和 Linux 沙箱属于适配/宿主层，不得反向定义 Kernel 的状态语义。
6. 审计与对账模块提供证据，不得把“存在收据”推断为外部副作用一定成功。
7. CLI 是组合入口，不应把业务状态机复制到应用层。

新增跨模块依赖前，先确认是否能通过 `contracts` 中的接口或构造参数注入完成；避免为了方便直接导入另一个模块的内部实现。

## 五、改动时的检查清单

- [ ] 是否修改了公共合同？同步更新全部调用者和协议测试。
- [ ] 是否改变事件结构或顺序？更新恢复校验、对账逻辑和 ADR。
- [ ] 是否改变工具执行路径？验证拒绝、取消、并发、租约丢失和未知结果。
- [ ] 是否改变 Provider 流处理？验证截断、乱序、重复、非法 JSON 和中止。
- [ ] 是否改变持久化？验证事务冲突、进程崩溃和重新打开。
- [ ] 是否改变 Linux Host？在真实支持环境中验证 namespace、cgroup、seccomp 和文件/网络边界。
- [ ] 是否更新中文文档索引和模块说明？
