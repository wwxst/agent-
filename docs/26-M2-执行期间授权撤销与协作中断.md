# 26 · M2 运行中授权重新校验与撤销栅栏

> 状态：已为持久 `SqliteControlAuthority` 模式下的 HTTP Command Dispatcher 实现**执行期间凭据版本重新校验、协作式中断和未决 Turn 保守停机**。不是 OS 强制沙箱、实时杀死进程、远程鉴权或外部副作用回滚机制。原临时 `principals` 内存模式不具备版本感知的持续授权，此增强只适用于显式启用 `authority` 的 HTTP 分发路径。

## 身份与执行凭据边界

### 授权时产生不可由客户端构造的内部 Grant

当 `POST /v1/sessions/:id/commands/:commandId/dispatch` 进入 HTTP 服务时，`SqliteControlAuthority.authorizeGrant()` **在同一 SQLite 事务中**验证当前 Token/Session/`command.dispatch` 权限、提交 `authorize` 审计，并捕获：

```ts
interface RuntimeAuthorizationGrant {
  principalId: string;
  credentialVersion: number;
  sessionId: string;
  permission: ControlPermission;
}
```

Grant 不出现在 HTTP 请求体或响应里、不保存 Bearer 明文、不授予新权限。它是受信本地代码传入 `ManagedSessionRunner.dispatchCommand(..., ()=>authority.assertGrant(grant))` 的绑定证据；不应该由模型、技能、未受信工具或远程客户端提供。

`SqliteControlAuthority.assertGrant(grant)` 以 SQLite `BEGIN IMMEDIATE` 读取最新 Principal 状态，检查凭据版本未改变、未被撤销、Session 仍被允许、分发权限仍存在，然后把 `recheck/allowed` 或 `recheck/forbidden` 持久写入 `control_authorization_audit` 才返回。DB/审计发生异常时**不予放行**；轮换版本或永久撤销都会使旧 Grant 失效。每次重检可能新增一条审计记录，部署方需管理增长与保留策略。

### Runner 中的重检与协作式中断

`ManagedSessionRunner.withLease()` 将已有 Writer Lease Guard 与可选的 `executionAuthorization` 组合：

1. **在首次 Command→Turn 绑定前**检查；过期凭据无权写入新绑定事件或调用模型；
2. 在运行期间，Runner **每个租约续租心跳**检查；模型正异步等待时也能发现撤销（并非硬实时）；
3. Kernel 的 `verifyExecution()` 在 Model Step、流事件、上下文摘要和工具执行边界继续检查；
4. Guard 检查失败（版本失效或授权审计不可写）时调用 `fenceActiveTurn(sessionId,'AUTHORIZATION_REVOKED')`，向模型和 Tool Host 传递 `AbortSignal`，不允许再开始后续 ToolCall；
5. 如果撤销发生于 Turn 活动期间，**即使此时尚未调用工具，也不写虚构的 `turn.failed`/`turn.cancelled`/`turn.completed`**；此 Turn 保留未决事实，重开要求 `RECOVERY_REQUIRED`。若 Tool Intent 已落库、Host 已 STARTED，则沿用双账本只读对账与人工核查。

调度器还明确透传 `AUTHORIZATION_REVOKED`（与 `LEASE_LOST` 同级），不会将其误包装成普通 `TOOL_ERROR`。API 在该情况下返回固定结构 `409 {error:'AUTHORIZATION_REVOKED'}`，不会回显提示词、Token 或数据库异常。

## 并发、撤销与可见性

- 撤销与 `assertGrant` 使用 SQLite 写事务串行化，**撤销 COMMIT 后新开始的重检必须失败**；在撤销事务之前已经通过的某次重检仍可能允许正在执行中的动作继续推进到下一个检查点。因此不是外部执行与授权撤销同事务的严格线性化。
- 心跳检测为协作式；若事件循环被同步代码长时间阻塞、Provider 忽略 AbortSignal 或 Tool Host 持有 OS 资源，**无法强制及时停止**，也不承诺回滚/抵消既有副作用。
- 未经 HTTP 持久授权路径启动的本地 `runTurn()`、旧内存 `principals` 模式、外部直接构造 Kernel 的宿主不会自动获得这一身份语义。部署方必须使用受信控制面并注入正确 Guard。
- 重新通过新 Token 认证的重复 Dispatch 只读取旧命令与 Turn 状态，不会因此自动重放或复活已失效的执行。原始 Writer Lease/Fencing、Command ID 幂等、Tool Intent/Receipt、Host STARTED 和审计边界全部保留。

## 已知限制与下一步

- 不提供 Token 版本与最终 Host 副作用**同一事务**的强制审计，也没有进程隔离、Linux seccomp、Filesystem Mount/网络 Namespace 等 OS 沙箱；
- 无跨进程广播/秒级强制撤销保证，不支持停机后自动恢复未决 Turn，不会因为权限恢复而自动继续；
- 授权审计表本身不具备对同 OS 写入者的加密不可篡改属性，需外部安全审计保管；
- 不宣称旧内存模式具备实时撤销；后续建议弃用其生产使用，仅作为受限开发测试配置；
- 下一阶段应单独引入 **OS 级 Tool Host 强制隔离**和经过真实身份绑定的高风险工具审批，不打开任何高风险工具运行权限。
