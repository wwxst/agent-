# Agent 内核技术路线：决策状态

> **状态：尚未最终决定（OPEN）**。更新：2026-10-31。当前仓库仅保存研究文档，不存在可运行的替代内核实现。

## 已较稳定的设计方向

需保护的不是某个框架或编程语言，而是**执行前意图、独立授权、权威事件、可信收据、结果未知阻断以及恢复安全**等不变量。这些原则可以被自研 Loop 或成熟 Agent Core 的受控适配层满足。

## 四种主要候选路线

| 方案 | 主要优点 | 未解决问题 | 当前状态 |
| --- | --- | --- | --- |
| 保留并重建自研 TS Loop | 完全控制事件、租约与 Host 屏障 | 代码维护负担、端到端产品成熟度 | 候选，未定 |
| Pi Agent Core + 可信适配层 | 低层循环和异步事件钩子适合做薄适配实验 | 并行存储故障、截断/UNKNOWN 语义、额外持久层 | **优先做实验，不等于已采用** |
| DeepSeek Harness 作为基础 | Scope 和工具/Session 组合具启发性 | 运行时依赖、嵌入成本、隔离边界需复核 | 候选，未定 |
| Codex/Claude Code 的机制参照 | 状态、安全、工具权限与产品交互经验丰富 | 直接复用/嵌入难度与许可条件 | 主要作研究参照 |

实际选择前还应检查许可、NOTICE、依赖合规和版本可维护性。静态源码研究**不能代替**真实适配测试。

## 必须完成的可比实验

1. 同样的工具调用序列在各候选下执行：按 A/B 原调用顺序构建模型上下文，记录真实完成与收据顺序。
2. Intent 持久化失败，确保真实工具没有开始执行。
3. 并行工具完成回调存储失败，等待其他在途任务收敛或记录 UNKNOWN。
4. 流截断、重复调用 ID、参数不完整时禁止副作用。
5. Lease 丢失、取消、权限撤销均不被伪装成成功或可安全重试。
6. 测量适配代码量、外部依赖、测试覆盖、性能与升级成本。

## 决策升级条件
