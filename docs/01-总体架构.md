# 01 · 总体架构与依赖边界

> 状态：设计草案；代码目录仅为推荐结构，尚不存在实现。

    Public API / Event Stream

## 二、模块职责和禁止依赖

| 模块 | 负责 | 禁止承担 |
| --- | --- | --- |
| kernel-core | Agent Loop、Turn 状态、调度、预算、运行控制 | 直接访问真实文件系统、网络凭据、UI |
| providers | 模型接口、增量数据规范化、用量与错误 | 改写 Session 状态或执行本地命令 |
| context | 构建模型上下文、压缩、留存规则、预算估算 | 修改 Tool Host 权限 |
| sessions | 会话索引、Turn 入队与恢复、状态转换 | 模型厂商专用语义 |
| events | 持久日志、快照、订阅、去重、重放 | 执行外部副作用 |
| tools | 工具定义、参数 Schema、调用身份、执行调度 | 自行绕过策略直接调用宿主 |
| policy | 风险分类、能力授予、审批状态、授权过期 | 充当 OS 沙箱 |
| tool-host | 工作区边界、隔离、进程管理、文件操作、审计 | 决定模型推理下一步 |
| extensions | Hook、Skill、MCP、扩展注册及生命周期 | 在未授权情况下改变内核不变量 |
| api | HTTP/WebSocket 等客户端适配和版本协商 | 直接写内部数据库状态 |

**依赖方向**：公共 DTO 与类型在底层；Kernel 依赖接口，不依赖具体 Provider、具体 DB 或具体 Tool Host。Host 仅通过契约回报结果，不直接访问 Agent 的私有内存。

目录是建议，不预设需要 Monorepo 或必须使用 Rust。v0.1 首选 TypeScript/Node（具体版本和存储选型在实现前经 ADR 固化）；Rust 可以在明确宿主性能/隔离需求后引入，不能把“用 Rust”误认为已有安全边界。

## 四、关键边界

### Kernel 与 Tool Host

- Kernel 发送带调用 ID、会话/Turn 身份、工具版本、参数和授权上下文的请求。
- Tool Host 必须再次校验文件路径、网络许可、命令范围、隔离环境与超时。
- 宿主产生分级结果：成功、明确失败、取消、未知结果。
- 重连或崩溃后的重试策略取决于工具是否幂等；高风险操作不得自动重试。

### Kernel 与 Provider

- 标准化模型消息与 ToolCall 片段；不允许模型任意构造“已获审批”事件。
- Provider 特性不足时报告清晰的能力缺失，不通过静默退化伪造执行成功。
- 隐式推理内容不应意外写入用户可见记录；只存储协议要求的、安全允许的摘要信息。

### Kernel 与客户端

- 写操作通过命令 API；读操作通过事件流和查询。
- 客户端请求使用幂等键，事件使用会话内单调序号。
- 所有命令在服务端验证所有权、会话与活跃 Turn 关系，不信任前端传入的权限字段。

## 五、部署阶段

**阶段 A（v0.1）**：一个 Node 服务进程加一个受限工具执行器（允许独立子进程）；本地数据库，单节点。

**阶段 B**：将 Tool Host 独立进程/容器化，支持断线后握手、能力协商和执行审计。

**阶段 C**：按需要增加远程 Host；要求明确的主机身份、用户确认和会话级执行位置，不允许远程失败后偷偷落到本地执行。

## 六、禁止的捷径

- 在 UI 组件中直接调用模型、Shell 或写数据库。
- 在 Agent Loop 中导入 Node 文件系统 API 来执行模型发出的任务。
- 每新增一个 Provider 就扩展一套独立的 Agent 状态机。
- 用字符串日志充当唯一的会话状态来源。
- 将“已提示用户”误判为“已获得系统授权”。
